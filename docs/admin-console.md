# 아이콤 관리자 페이지

2026-09-08 · Stitch의 운영 현황 디자인을 기반으로 구현.

## 접속과 관리자 계정

일상적인 계정 등록·관리는 **관리자 계정 메뉴(`/admin/accounts`)**에서 한다. 로그인한 관리자가 새 이메일과 비밀번호·확인을 입력하면 Supabase Auth에 관리자 역할과 함께 생성하며 즉시 로그인할 수 있다. 별도 초대 메일이나 설정 파일이 필요하지 않다. 관리자 목록에서 비밀번호를 변경할 수 있고, 본인 비밀번호 변경 시 로컬 세션을 종료한 뒤 다시 로그인한다. 비밀번호 원문을 조회·반환·로그·파일 저장하지 않는다. 일반 사용자 계정의 승격이나 비밀번호 변경, 관리자 삭제·권한 회수는 이 화면에 포함하지 않는다. 모든 기존 관리자는 동일한 계정 관리 권한을 갖는다.

- 로그인: `/admin/login`, 대시보드: `/admin`.
- Supabase 이메일·비밀번호 인증과 서버가 관리하는 `app_metadata.role = "admin"`을 함께 확인한다.
- 이메일 확인이 완료되지 않은 계정, 일반 사용자, 익명 사용자, 이용 제한 계정은 거부한다. 사용자가 수정할 수 있는 `user_metadata`는 권한 판단에 사용하지 않는다.
- 각 페이지·데이터 조회·서버 액션에서 권한을 다시 확인한다. 레이아웃 숨김만으로 보호하지 않는다.
- 인증 서버의 `/auth/v1/user`를 매 요청 조회한다. JWT를 로컬에서 해석한 역할을 신뢰하지 않는다. 토큰 만료·권한 제거·인증 서버 장애 시 로그인으로 이동한다.
- 접근 토큰은 HttpOnly / SameSite=Strict / `/admin` 경로 쿠키에 저장한다. 프로덕션은 Secure 쿠키이므로 HTTPS가 필요하다. 만료는 토큰 수명 또는 1시간 중 짧은 값이며 자동 연장하지 않는다.
- 로그아웃은 동일 출처 POST만 받고 Supabase 세션 종료를 요청한 뒤 쿠키를 제거한다. 외부 서비스 장애 시에도 로컬 쿠키를 제거한다. 이미 유출된 JWT의 즉시 무효화를 보장하는 별도 세션 저장소는 구현하지 않았다.
- 서버 키는 `SUPABASE_SECRET_KEY`, 프로젝트는 `SUPABASE_URL`. 브라우저에 키나 원본 API 오류를 전달하지 않는다.

아래 스크립트는 최초 관리자 계정이 전혀 없는 환경의 초기 설정용이다. 기존 계정 승격·비밀번호 초기화는 이 스크립트에서 하지 않는다. 관리자 로그인 이후에는 위 관리자 계정 메뉴를 사용한다.

```bash
node --experimental-strip-types scripts/admin/create-admin.ts --email 실제관리자이메일 --origin http://localhost:3002
```

비밀번호를 생성하거나 저장하지 않는다. Supabase 초대 계정과 일회용 설정 링크를 만들고 `.local/admin/계정ID-setup.html`에 파일 권한 600으로 보관한다. 이메일은 발송하지 않는다. 해당 파일을 브라우저에서 열어 `/admin/setup`으로 이동하면 본인이 비밀번호를 설정한다. 링크 토큰은 URL fragment로 전달해 서버 요청 URL에 남기지 않고, 새로고침과 재시도를 위해 설정이 성공할 때까지 유지한다. 제출할 때 fragment를 읽어 전달하고, 비밀번호 설정 성공 후 주소 표시줄에서 제거한다. 초대 확인 후 서버가 관리자 권한을 재검증하고 최대 10분의 HttpOnly 설정 쿠키로 저장 실패 재시도를 지원한다. 비밀번호 설정 후 쿠키를 지우고 다시 로그인하도록 한다. 파일은 Git에 포함하지 않으며 링크를 공유하지 않는다. 사용자가 지정한 첫 관리자 계정을 등록했고, 실제 DB에서 관리자 역할·비밀번호 미설정 상태를 확인했다.

인증 기준: [Supabase getUser](https://supabase.com/docs/reference/javascript/auth-getuser), [사용자 메타데이터](https://supabase.com/docs/guides/auth/users).

## 구현 범위

| 메뉴 | 동작 |
| --- | --- |
| 대시보드 | 실제 정책 수, 품질 상태, 출처별 저장량, 최근 실행 조회. 사용자 수는 현재 조회 페이지 범위를 명시 |
| 관리자 계정 | 관리자 전용 목록, 이메일·비밀번호 등록, 기존 관리자 비밀번호 변경. 중복 이메일은 기존 계정을 변경하지 않고 거부 |
| 사용자 관리 | 실제 인증 계정 목록, 마스킹 이메일, 가입·로그인 시각, 이용 제한 상태, 페이지 이동. 제재·계정 삭제는 미구현 |
| 정책 관리 | 출처·정책명 검색, 페이지 이동, 정책 상세 펼침, 공식 링크, 품질 상태별 이력 조회와 다음 커서 |
| 정책 수집 | 출처·검색어 설정, 실행 목록, 발견·성공·실패·대기 건수, 중단 사유, 호출 예약량, 이어서 수집 |
| 커뮤니티 / 신고 | 메뉴·탭·목록 구조. 사용자 커뮤니티 저장·신고 백엔드가 없어 연동 준비 상태를 명시 |
| 공지 / 알림 | DB에 초안 작성·수정·보관, 동시 수정 충돌 방지. 사용자 게시·외부 발송은 미연결 |

공지 초안은 `admin_notices`에 저장한다. RLS 활성화, 일반 역할 접근 차단, 서버 역할에 조회·추가·수정만 허용한다. `20260908063708_admin_notices.sql`을 개발 DB에 적용하고 마이그레이션 이력·DB 타입을 갱신했다.

## 수집 실행

웹 실행은 `POLICY_SYNC_ENABLED=true`와 해당 출처 API 키가 있어야 한다. 한 번의 요청은 최대 5개 정책 / 10회 API 호출 / 일일 예약 상한 100회로 제한한다. 요청 종료 후 저장된 실행 ID로 재개한다. 웹 요청에 맞춘 작은 배치이며 수천 건을 한 HTTP 요청이나 예약 작업으로 처리하지 않는다. 전체 범위는 검색어를 비워 지정한다. 호출 예산·중단·재개·목록 변경 계약은 [자동 수집 운영 문서](./policy/policy-automatic-quality.md)를 따른다.

수집 액션은 Node 서버에서 실행되며 배포 플랫폼에 충분한 실행 시간이 필요하다(`maxDuration=300`은 플랫폼 지원 시 적용). 프로세스가 중단되면 잠금 만료 후 이력에서 재개한다. 대규모 정기 수집은 별도 작업 실행기 연결이 필요하다. 이번 관리자 구현에서는 새 수집을 실행하지 않았다.

## 검증과 한계

- 관리자 인증·데이터 조회·공지 저장소·서버 액션 테스트. 일반 사용자와 위조·만료 토큰 거부, 쿠키 속성, 무권한 작업 방지, 로그아웃 출처 검사, 초안 충돌·권한 확인.
- 실제 개발 서버에서 관리자 6개 경로의 비로그인 접근 차단 확인.
- 실제 DB의 정책 목록·인증 사용자 목록·공지 저장소 읽기 연결, 공지 테이블 일반 역할 차단 확인.
- 격리된 예시 데이터를 이용한 관리자 화면 시각 확인. 실제 인증을 우회하는 코드나 미리보기 경로는 제품에 포함하지 않는다.
- 타입·ESLint·webpack 프로덕션 빌드 확인. 기존 환경의 Turbopack 문제를 피하려면 `npm run build -- --webpack` 사용.
- 실제 관리자 로그인 후 전체 화면을 탐색하는 검증은 계정 설정 후 필요하다. 자동 승인 검토가 임시 관리자 생성·로그인 정보 보관을 거절해, 임시 계정은 만들지 않았다.

```bash
node --experimental-strip-types --test src/features/admin/server/*.test.ts
npm run build -- --webpack
```
