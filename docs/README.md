## 유지할 결정 사항

- 일반 사용자 로그인은 **카카오·네이버·구글**만 대상으로 한다. 인증 대기라는 사용자 상태·지표·승인 흐름을 추가하지 않는다. 관리자 이메일·비밀번호 인증 및 서버 권한 검사는 별도 운영 계약이다.
- 공개 관심 분야는 **임신·출산, 양육·보육, 돌봄, 의료·건강, 아동 교육, 주거·생활지원**의 6개다. 아동 교육을 양육·보육에 합치지 않는다.
- 기존 관련성 평가의 7개 분야와 UI의 6개 분야 라벨은 서로 다른 목적의 분류다. [관련성 기준](policy/work/classification.md)과 [라벨링 기준](policy/work/classification.md)을 구분한다.
- 라벨 저장·AI 보조 검수 적용과 공개 라벨 검색·자격 비교는 다른 단계다. `VERIFIED`라는 저장 상태를 인간 검수 완료·공개 승인·수혜 확정으로 해석하지 않는다.
- 관리자 헤더·사이드바는 보호된 공통 레이아웃에서 관리한다. 정책 목록의 원문 상세와 수집 제외 정책 상세는 모달이다.
- 디자인 개선은 [DESIGN.md](../DESIGN.md)를 목표로 요청 범위에서 점진 적용한다. 기존 UI 기록은 현재 구현 상태이며, 문서 작성만으로 화면 적용이 완료된 것은 아니다. 후속 기능을 연결할 때 전체 화면을 다시 바꾸지 않는다. 미연동 기능·집계를 실제 동작·수치처럼 표시하지 않는다.

## 문서 통합 결과

- 정책 문서 전체를 검토해 [짧은 사용자 안내](policy/README.md), [작업용 계약·계획](policy/work/README.md), 날짜별 근거 기록으로 분리했다. 수집·저장, 공통 데이터, 분류·라벨, 추천 계약을 주제별로 통합하고 중복된 원문 문서는 삭제했다.
- 관리자 운영 설명과 여러 차례 추가된 UI 기록을 [관리자 콘솔](admin-console.md)로 통합했다. 이전 [UI 관리자 문서](ui/admin-console.md)는 안내 링크로 남긴다.
- 공개 UI의 현재 동작은 [공개 UI 적용 기준](ui/stitch-implementation.md)에 모았다. 변경 순서에 따른 13개 QA 항목은 [과거 QA 기록](archive/ui-qa-history-20260909.md)으로 보관하고 현재 기준과 구분한다.
- README의 초기 구상은 [초기 프로젝트 개요](archive/project-overview-original.md), 관리자 화면의 상세 변경 이력은 [관리자 UI 이력](archive/admin-ui-history-20260909.md)으로 보관한다.
- 정책의 현행 계약은 work/, 과거 검증·출처 분석은 records/에서 관리한다. 사용자 안내에 기술 명세와 실행 기록을 복제하지 않는다.
- `docs/fixtures/`는 검증 원본·결과다. 설명 문서 중복과 달리 삭제·내용 병합하지 않는다. `.local/`과 `/tmp/`의 개인·임시 산출물은 저장소만으로 재현 가능하다고 보지 않는다.

## 갱신 규칙

현재 동작은 해당 기준 문서 한 곳에서 갱신하고, 작업 상태는 [다음 작업](next-steps.md)에 반영한다. 실행 결과에는 날짜·대상 환경·실제/합성 데이터·검증 범위를 적는다. 과거 문서의 ‘완료’나 고정 건수를 현재 운영 상태로 복사하지 않는다. 파일을 옮길 때는 기존 진입 링크를 안내 문서로 유지하거나 상대 링크를 함께 수정한다.
