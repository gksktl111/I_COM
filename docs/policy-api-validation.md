# Gov24 API 실제 표본 검증

상태: 1단계 진행 중. 인증된 실제 표본 미수집. 후속 계약·DB 스키마 확정 전 대기.

## 작업 인계 (2026-09-08)

사용자 요청에 따라 이번 작업은 1단계 탐색 도구 구현·합성 검증·문서 정리까지 진행하고 종료한다. 전체 계획의 완료를 뜻하지 않는다. 작업 브랜치는 `feat/policy-ingestion`이며 기존 계획서의 사용자 수정은 보존했다.

구현 산출물:

- `scripts/policy/probe-gov24.ts`: 후보 검색과 선정 표본의 상세·지원조건 탐색 CLI.
- `src/features/policy/server/gov24/probe.ts`: 제한된 요청, 비밀 제거, 페이지 관찰, 필드 타입·빈 값 통계.
- `src/features/policy/server/gov24/probe.test.ts`: 실제 API를 호출하지 않는 합성 회귀 검증.
- `.env.example`, `npm run policy:probe`, `npm run policy:test`, [실행 안내](./policy-probe.md).
- 공식 필드 자료와 조건 코드 설명표. 실제 표본 ID·실응답 fixture는 아직 없음.

다음 재개 순서:

1. `.env.local`에 승인된 `GOV24_API_KEY`가 설정되었는지 값 노출 없이 확인한다.
2. `policy:probe search`로 실제 후보를 조회하고 5~10개의 ID·선정 이유·목록 원본 근거를 선택한다.
3. `collect`와 시차 재조회·페이지 비교로 세 API의 실제 응답을 확보한다.
4. 이 문서의 관찰표·조건 코드표를 채우고 비밀 제거를 검토한 실제 fixture를 추가한다.
5. 1단계 완료 기준을 통과한 뒤에만 `policy-data-contract.md`, `policy-db-schema.md`를 확정한다. 이후 개발용 Supabase 대상 확인 → 저장/RPC → 정규화 → 수동 파이프라인 → 통합 검증 → 예약 2회 확인 순서로 진행한다.

DB 마이그레이션·정책 반영·예약 등록은 아직 수행하지 않았다. Supabase MCP 연결 성공만으로 애플리케이션용 서버 키 준비나 개발 환경 격리를 확인한 것으로 취급하지 않는다.

## 현재 확인한 근거

- 기존 코드의 `npm run build` 통과(린트·TypeScript·Next.js 빌드 포함).
- Supabase MCP의 프로젝트 URL 조회와 `SELECT 1` 성공. 연결 대상은 `visumyadkxleiqtxokqg`. 개발·검증용 여부와 애플리케이션 서버 키는 별도 확인 대상이다.
- `.env.local`에서 변수 이름과 설정 유무만 확인했으며 `GOV24_API_KEY`, `SUPABASE_URL`, `SUPABASE_SECRET_KEY`는 없었다. 비밀값은 출력하지 않았다.
- [공식 Swagger](https://infuser.odcloud.kr/api/stages/44436/api-docs?1684891964110)를 다시 조회하고 [명세 필드 자료](./fixtures/gov24/official-schema.json)에 타입·설명을 기록했다. 이 자료는 실응답 fixture가 아니다.

## 정책별 관찰

아직 선정된 실제 정책은 없다. 기본 목표 8개(중앙 4, 시도 2, 동일 시군구 2)를 실제 서비스명·요약·지원대상·기관을 검토하여 선정한다. 기관 소재지만으로 적용 지역을 결정하지 않는다.

## 필드별 대조

명세 타입의 전체 목록은 `official-schema.json`의 `models`에 있다. 실제 관찰 후 각 필드별로 아래 표를 채우며, 관찰하지 않은 타입을 내부 계약으로 확정하지 않는다.

| 엔드포인트 | 필드 | 명세 타입 | 관찰 타입 | 누락/null/빈 문자열/공백 빈도 | 최대 길이·예시 | 내부 타입 제안 | 상태·근거 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 세 API | 서비스ID | string | 미관찰 | 미관찰 | 미관찰 | 미확정 | 명세만 확인 |

조건 코드는 [코드 관찰표](./policy-code-observations.md)에 별도로 관리한다.

실제 표본 확보 후 목록/상세 공통 필드의 충돌, URL·HTML·문단·숫자 의미, 조건 코드 값과 설명을 대조한다. 합성 테스트 통과는 실응답 검증을 대체하지 않는다. 사용자 수정 중인 원 계획서는 보존하고 진행 근거를 이 문서에 기록한다.
