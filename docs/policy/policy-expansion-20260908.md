# 전체 범위 수집 1차 결과

2026-09-08 개발 DB 확인. 기존 50개에서 **215개**로 증가했다. 출처별 레코드이며 출처 간 고유 정책 수는 아니다.

설정은 [automatic-all.json](../../scripts/policy/automatic-all.json): 검색 제한 없음, 페이지 크기 50, 최대 1000페이지, 출처별 UTC 일일 예약 호출 상한 100회. 실제 공공데이터 계정 할당량을 측정한 값은 아니다.

| 출처 | 현재 저장 | 이번 실행 처리 성공 | API 응답 전체 건수 | 이번 실행 호출 |
| --- | ---: | ---: | ---: | ---: |
| 복지로 중앙 | 85 | 49 | 461 | 50 |
| 복지로 지자체 | 99 | 97 | 4,763 | 100 |
| Gov24 | 31 | 23 | 10,956 | 100 |

이번 실행에서 169개를 처리했고 중앙의 기존 4개는 갱신했다. 순증은 165개다. 중앙은 앞선 양육 검색에 사용한 50회를 합쳐 오늘 예약량이 100회가 됐다. 다른 출처도 각각 100회에 도달했다. 응답 전체 건수는 목록 탐색 중에 관측한 값이며 전체 수집 완료·중복 제거·육아 정책 분류를 뜻하지 않는다.

## 품질과 실행 종료

- 현재 정책 215개 모두 품질 평가 대응. REVIEW 215, ERROR 0, 현재 미평가 0.
- 필수 6개 항목 존재 합계 1,290/1,290. 내용 정확도나 자격 비교 준비 완료가 아니다. 비교 준비 완료 0.
- 모든 실행은 CALL_BUDGET으로 일시정지(실행 테이블 PARTIAL). 전체 목록 수집은 아직 미완료다. 잠금 해제 확인.
- 지자체 첫 50개 뒤 목록 2페이지 오류가 있었지만 한 차례 재개하여 정상 응답(50개, 고유 ID 50개)을 확인하고 나머지 예산까지 처리했다.
- Gov24는 15개 저장 후 저장 경로 오류로 프로세스가 종료됐다. 최초 원인은 확정하지 못했다. 잠금 만료 후 같은 실행에서 재개해 8개를 추가 처리했다. 재개 시 같은 저장 오류는 재현되지 않았다.
- 민감한 요청 정보가 포함될 수 있는 진단 응답은 `.local/policy-sync/automatic`에만 보관한다. 관리자용 최종 품질 보고서는 같은 경로의 `expanded-quality-report.json`이다.

## 다음 재개

일일 예약일은 UTC 00:00(KST 09:00)에 바뀐다. 이번 실행 시점 기준 다음 예약일은 2026-09-09 KST 09:00이다. 예약 실행기는 연결되지 않았으므로 자동으로 다시 실행되지는 않는다.

```bash
POLICY_SYNC_ENABLED=true npm run policy:auto -- --provider central --resume 87f0678c-b4f1-4bb4-a9bf-2153cf37ba57 --call-budget 100
POLICY_SYNC_ENABLED=true npm run policy:auto -- --provider local --resume 547a59cf-f9b3-4d86-be97-318be3ef4455 --call-budget 100
POLICY_SYNC_ENABLED=true npm run policy:auto -- --provider gov24 --resume 8a75d68a-9a14-4ae0-ac8a-02568b5902fd --call-budget 100
```

관리자 정책 수집 화면에서도 재개할 수 있다. 이번에 CLI 설정(페이지 크기 50·검색 범위 등)을 웹 재개에서 기본값으로 바꾸던 문제를 수정했다. 저장된 설정을 조회해 그대로 사용하고 웹 배치 예산은 기존 10회/5개로 유지한다. 재개 회귀 검사와 기존 접근 차단 검사, 타입·린트·webpack 빌드 통과.
