# 맞춤 정책 라벨링 기준 — 현재 6개 카테고리

작성일: 2026-09-08 · 버전: `interest-taxonomy-v2-draft` · 상태: 검토 초안

이 문서는 현재 맞춤 정책 찾기의 카테고리를 기준으로 정책을 분류하고 검수하는 기준을 제안한다. 6개 분야의 자동 제안·검수 이력 저장 코드와 마이그레이션을 구현했고, 활성 후보 1,000건의 원문을 전수 AI 보조 검수하여 로컬 PGlite에 저장·검증했다. **사용자 승인 후 개발 DB에 마이그레이션과 1,000건 검수 결과를 적용하고 활성화 자동 제안·재실행을 검증했다.** 공개 검색은 현재 키워드 조회를 유지하며 라벨 기반 검색·자격 비교는 연결하지 않았다.

아래 기록 규격에는 후속 논리 설계도 포함한다. 실제 구현된 저장 필드·명령·검증 결과와 원격 적용 상태는 [라벨링 실행 안내](./policy-labeling-runbook.md)를 기준으로 한다. 이번 검수는 `AI_ASSISTED`이며 인간 검수나 공개 승인 완료를 뜻하지 않는다.

## 1. 목적과 적용 범위

현재 화면은 관심 분야 하나를 필수 선택하지만, 조회는 정책 원문의 넓은 키워드 일치에 의존한다. 상세 답변은 세부 필터에 아직 연결되지 않았다. 이를 다음 순서로 개선한다.

1. 실제 지원 목적에 맞는 **분야·세부 유형**을 검수해 다른 분야의 정책이 섞이는 문제를 줄인다.
2. **지원 대상과 적용 범위**를 구분해 아동·청소년 본인과 가족을 위한 정책을 찾는다.
3. 근거와 조건 관계를 검수한 **자격 규칙**을 입력값에 연결한다. 분류 라벨만으로 신청 가능 여부를 판정하지 않는다.

사용자는 한 분야를 선택하고, 정책에는 복수 분야를 부여할 수 있다. 예를 들어 임산부 진료비 지원은 임신·출산과 의료·건강의 실제 지원 경로를 모두 가질 수 있다. 결과를 줄이기 위해 정책마다 분야 하나를 강제하지 않는다.

서비스 범위는 임신·출산 가구뿐 아니라 일반 아동·청소년 본인, 자녀를 양육하는 보호자와 가구를 포함한다. 장애·저소득·한부모 등의 특성은 선택적인 대상 조건이지 모든 정책의 기본 요건이 아니다. ‘아동’, ‘청소년’, ‘자녀’의 연령을 하나의 임의 상한으로 통일하지 않고 원문의 정의를 보존한다.

### 기존 문서와의 관계

- [관련성 기준](./policy-relevance.md): 서비스 범위에 들어오는 정책 후보인지 판단하는 기존 7개 분야 평가다. 현재 활성 후보라는 사실은 이 문서의 6개 분야 라벨 검수 완료를 뜻하지 않는다.
- [공통 논리 데이터 계약](./policy-common-data-contract.md): 원본 근거, 대상 인물, 조건 관계, 정보 상태, 버전과 검수 원칙을 따른다.
- [검색 요구사항](./policy-search-requirements.md): 자격 비교와 공식 출처 표시 원칙을 따른다.
- [현재 분야별 입력](../ui/interest-questions.md): 1단계 관심 분야·거주지, 2단계 분야별 상세 정보와 연결한다. 과거 문서의 입력 순서보다 현재 UI 문서를 우선한다.

이 문서는 현재 6개 카테고리의 분류 사전과 검수 기준을 구체화한다. 기존 수집·관련성 평가·공개 승인 상태를 덮어쓰는 문서가 아니다.

## 2. 분류 단위와 공통 판정 원칙

### 분류 단위

기본 단위는 하나의 정책이다. 다만 통합 신청 서비스나 복합 사업은 **실제 지원 경로별 하위 서비스**를 분류 단위로 나눈다. 분야·대상·조건은 같은 경로에 묶어 저장한다.

예를 들어 한 통합 사업에 ‘임산부 건강검진’과 ‘다자녀 주거 지원’이 함께 있어도 임산부의 연령 조건을 주거 지원 경로에 적용하지 않는다. 결과 카드가 정책 단위라면 해당 분야에 해당하는 하위 서비스를 이유로 표시하고 같은 정책을 중복 노출하지 않는다.

### 근거 우선순위

1. 현재 적용 중인 원문의 지원내용·지원대상·선정기준에서 실제 급여나 서비스를 확인한다.
2. 사업 목적과 공식 제목으로 의미를 보완한다.
3. 제공자 분류 코드와 키워드는 자동 분류 후보를 만드는 보조 근거로 사용한다.

제목만으로 내용이 충분히 특정되지 않으면 검토 대상으로 남긴다. 서류 목록, 정책 배경, 제외 대상, 부정문, 기관명에 나온 단어만으로 라벨을 확정하지 않는다. 원문이 충돌하면 최신 수집일만으로 한쪽을 선택하지 않는다.

각 분야 라벨에는 그 분야의 실제 지원 목적을 입증하는 근거가 필요하다. 보조 분야도 주 분야와 동일한 근거 수준을 요구한다. 대상자가 부모라는 이유만으로 양육·보육을, 현금 지급이라는 이유만으로 주거·생활지원을 추가하지 않는다.

### 서비스 범위가 넓은 정책

일반 생계·주거·의료 사업을 일괄 제외하지 않는다. 아동·가족이 실제 포함되는 지원 경로가 원문에 확인되면 `general_inclusive` 대상으로 분류할 수 있다. 단순히 아동 제외 문구가 없다는 이유만으로 포함을 확정하지 않는다. 반대로 ‘부모’, ‘가족’ 단어가 없어도 아동 본인 지원 근거가 있으면 포함한다.

성인 전용, 노인 전용, 기업 전용 등 명시적으로 범위 밖인 경로는 제외한다. 신청자가 사업주여도 실제 지원이 육아휴직 등 가족 지원인 경우 신청 주체와 수혜자를 구분해 검토한다.

## 4. 세부 유형 사전

한 하위 서비스가 여러 실질적 지원을 제공하면 세부 유형도 복수 부여할 수 있다. `other`는 목적이 분명하지만 사전에 없는 유형이며 근거와 사전 확장 요청을 필수로 남긴다. 정보 부족을 `other`로 채우지 않는다.

| 상위 분야     | 세부 유형 코드                                                                           | 의미                                                                          |
| ------------- | ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 임신·출산     | `preconception`, `infertility`                                                           | 임신 준비·사전 지원, 난임 관련 지원                                           |
| 임신·출산     | `prenatal`, `birth_grant`, `postpartum`                                                  | 임신 중 지원, 출산 사건에 대한 급여, 산후 회복·조리 지원                      |
| 양육·보육     | `child_allowance`, `childcare_fee`                                                       | 양육비·수당, 어린이집·유치원의 기본 보육·교육 이용 비용                           |
| 양육·보육     | `childcare_access`, `parenting_service`                                                  | 보육시설 이용·접근, 양육 상담·교육·휴직 등 보호자의 양육 지원                 |
| 아동 교육     | `education_participation`, `learning_support`                                            | 아동·청소년 교육비·학용품·통학 등 참여 지원, 학습 지원                        |
| 돌봄          | `home_visit`, `center`, `afterschool`, `emergency`                                       | 방문 돌봄, 시설·센터 돌봄, 방과 후 돌봄, 긴급·일시 돌봄                       |
| 의료·건강     | `checkup`, `vaccination`, `treatment`, `medical_cost`, `rehabilitation`, `mental_health` | 검진, 예방접종, 진료·치료, 의료비, 재활, 정신건강 지원                        |
| 주거·생활지원 | `housing_access`, `housing_cost`, `moving`, `utilities`, `livelihood`, `food`            | 주택 공급·접근, 임대료 등 주거비, 이사, 공과금·에너지, 생계비, 급식·식품 지원 |

‘평일·야간·주말’은 돌봄의 세부 유형이 아니라 서비스 제공 시간 속성이다. ‘가정 양육·어린이집·유치원·학교’는 아동의 이용 상태이며 정책의 지원 유형과 별도로 기록한다. 질병명·장애 여부·소득은 분야 자체가 아니라 대상 또는 조건이다.

현재 6개 카테고리에 명확히 들어가지 않는 서비스 관련 정책은 `OUT_OF_TAXONOMY`로 보존하고 사전 검토 대상으로 둔다. 양육·보육이나 주거·생활지원에 편의상 몰아넣지 않는다.

## 5. 기존 7개 관련성 분야와의 연결

아래는 재검수의 출발점이며 자동 일대일 변환 규칙이 아니다.

| 기존 관련성 분야   | 우선 검토할 현재 카테고리       | 확인 사항                                                                            |
| ------------------ | ------------------------------- | ------------------------------------------------------------------------------------ |
| 임신·출산          | 임신·출산                       | 실제 지원 내용에 따라 의료·건강 등 복수 분야 검토                                    |
| 양육·보육          | 양육·보육                       | 단순 아동 언급과 직접 양육 지원 구분                                                 |
| 아동 돌봄          | 돌봄                            | 교육 강좌와 보호·돌봄 서비스 구분. 기존 문화·체육·일상생활 지원은 목적별 재분류      |
| 아동 의료·건강     | 의료·건강                       | 아동 대상 경로와 치료·예방 목적 확인                                                 |
| 아동 교육          | 아동 교육                       | 초중고 등 아동·청소년 지원 보존. 성인 전용 학비는 해당하지 않음                      |
| 가족 지원          | 실제 목적에 따라 분기           | 양육 상담, 정신건강, 생계 등으로 재검수. 관계 개선 등 사전 밖 목적은 OUT_OF_TAXONOMY |
| 신혼·자녀가구 주거 | 주거·생활지원                   | 신혼·자녀가구의 실제 지원 경로 확인                                                  |

기존 아동 돌봄에 포함된 관람료·문화·체육 활동 지원은 보호·돌봄 서비스로 자동 변환하지 않는다. 명확한 아동·청소년 교육 참여 목적이면 아동 교육, 생계 목적이면 주거·생활지원으로 검토한다. 순수 문화·체육 지원처럼 현 사전에 맞지 않으면 OUT_OF_TAXONOMY로 보존하며, 서비스 무관으로 판정하지 않는다.

기존 관련성 판단의 원본·버전·이력은 그대로 보존한다. `ACTIVE` 등 수집 후보 상태, 6개 분야 검수 상태, 공개 가능 상태, 조건 비교 가능 상태를 별개로 취급한다.

## 6. 라벨링 기록 규격

이 절은 논리 규격이다. 구현은 `assessment.categories`, `assessment.labels[]`의 분야·세부 유형·경로·원문 인용, `targets`, `reason`을 저장한다. 별도 `subcategories[]`나 `primary_category`, 구조화한 자격 규칙·인물별 관계·공개 승인 필드는 아직 구현하지 않았다. 자동 제안과 검수 이력은 분리하며 현재 유효한 원본·평가 버전과 일치하는 기록만 현재 라벨 뷰에 나타난다.

### 분야·대상 기록

| 항목      | 기록 내용                                                                                                                                                                |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 식별      | 정책 ID, 출처·외부 ID, 하위 서비스 ID 또는 정책 전체 범위                                                                                                                |
| 기준 원본 | 적용 스냅샷 ID·해시, 정제 버전, 원문 적용 연도·시점                                                                                                                      |
| 분야      | `categories[]`, `subcategories[]`와 각 상위 분야 연결. 대표 목적이 확인되면 `primary_category` 하나                                                                      |
| 대상      | `child`, `adolescent`, `pregnant_person`, `preconception_person`, `parent_guardian`, `newlywed_household`, `child_household`, `general_inclusive` 등 근거 있는 복수 대상 |
| 역할      | 신청자·수혜자·대리인·가구 구분. 역할별 대상 연결                                                                                                                         |
| 근거      | 원본 필드 경로, 문장, 공식 출처 링크, 어느 라벨을 지지하는지                                                                                                             |
| 판단      | 분류 상태, 판단 이유, 미해결 사유, 자동 제안 여부·사용한 규칙/모델 버전                                                                                                  |
| 검수      | 검수자, 검수 시각, 사전 버전, 적용 원본 버전, 변경 이유                                                                                                                  |

VERIFIED 분류에는 근거가 있는 categories가 하나 이상 필요하다. OUT_OF_TAXONOMY, OUT_OF_SCOPE 및 근거 부족 NEEDS_REVIEW는 분야 배열이 비어 있을 수 있으며 사유를 필수로 남긴다. 미확정 후보 라벨은 확정 라벨과 별도로 기록한다. 대표 목적을 하나로 정할 근거가 없으면 primary_category는 비워 둘 수 있고, 이것만으로 근거가 명확한 복수 분야의 검수를 막지 않는다.

주 분야는 정책의 대표적인 지원 목적이다. 독립적인 복수 목적의 우선순위가 불명확하면 임의로 정하지 않고 검수한다. 검색은 주 분야뿐 아니라 검수된 모든 해당 분야를 사용한다. 원문의 정책·하위 서비스별 연결 없이 라벨을 평면적으로 합치지 않는다.

### 분류 상태

| 상태              | 의미                                                   | 분야 검색 적용                          |
| ----------------- | ------------------------------------------------------ | --------------------------------------- |
| `PROPOSED`        | 자동·수동 초안, 검수 전                                | 검수 작업 목록에만 사용                 |
| `VERIFIED`        | 현재 원본의 해당 분류 범위를 검수 완료                 | 공개 요건도 통과한 경우 적용            |
| `NEEDS_REVIEW`    | 근거 부족·충돌·해석 보류                               | 확정 분야 결과에 자동 포함하지 않음     |
| `STALE`           | 원본 또는 사전 변경으로 기존 검수의 유효성 재확인 필요 | 영향받는 라벨의 검색 적용 중단          |
| `OUT_OF_TAXONOMY` | 서비스 관련성이 있으나 현행 6개 분류로 표현 불가       | 별도 검토·사전 확장 대상으로 보존       |
| `OUT_OF_SCOPE`    | 실제 지원 경로가 서비스 범위 밖                        | 해당 범위 검색에서 제외, 원본·이력 보존 |

자동 분류의 신뢰도 점수는 검수 상태를 대체하지 않는다. 상태는 정책 전체와 하위 서비스 중 어느 범위에 적용하는지 함께 기록한다. 한 경로의 보류·제외를 다른 검수 완료 경로로 전파하지 않는다.

구현된 `VERIFIED`는 원문 의미 검수 결과의 상태이며 `review_kind`로 `HUMAN`과 `AI_ASSISTED`를 구분한다. 이번 1,000건은 모두 AI 보조 검수다. `STALE`은 현재 별도 저장 상태가 아니라 스냅샷·전체 정제값 해시·정제 및 평가 버전 불일치에 따른 현재 뷰 제외로 구현했다. 위 표의 검색 적용은 후속 정책이다.

## 7. 자격 조건 구조화와 현재 질문의 연결

분야 라벨 검수와 조건 규칙 검수는 별도다. 아래 입력값이 있다는 이유로 비교 가능한 규칙이 생기지는 않는다.

| 현재 입력                | 정책에 필요한 의미                                   | 초기 적용 원칙                                                                  |
| ------------------------ | ---------------------------------------------------- | ------------------------------------------------------------------------------- |
| 관심 분야 하나           | 검수된 categories와 하위 서비스                      | 일치 분야의 후보 조회                                                           |
| 시도·시군구              | 적용 지역, 주민등록/실거주 기준, 기준일·거주기간     | 기관 소재지를 지역 조건으로 사용하지 않음. 주소 표기와 지역 코드 버전 연결 필요 |
| 가족 상황·출산 예정 시기 | 대상 사건, 임신·출산·산후 구분, 주수·사건 기준일     | ‘3개월 이내’ 같은 거친 구간을 정확한 예정일·임신 주수로 변환하지 않음           |
| 자녀 생년월일·출생월     | 어느 자녀의 연령인지, 만 나이/월령, 비교 기준일·경계 | 출생월만으로 경계 판단이 불가능하면 확인 필요                                   |
| 총자녀 수·전체 입력 여부 | 총자녀 수, 대상 자녀 수, 출생순위 중 정확한 속성     | 등록된 자녀 목록 길이로 다자녀·출생순위를 추정하지 않음                         |
| 보육·교육 이용 현황 (양육·보육·아동 교육 공통) | 시설·학교 이용/미이용 조건, 대상 자녀·기준일              | 동일 자녀에게 연령·이용 조건을 함께 적용                                        |
| 돌봄 시간·유형           | 실제 제공 시간·방식·이용 조건                        | 선호와 불일치는 관련도 정렬에 우선 사용. 자격 탈락으로 바꾸지 않음              |
| 의료·건강 지원 유형      | 실제 지원 목적과 검수된 세부 유형                    | 목적 일치로 후보를 좁힘. 미입력 진단·질환 조건은 확인 필요                      |
| 주거 형태·생활 지원 목적 | 현 주거 형태, 무주택·주택 소유 조건, 지원 목적       | 월세 거주를 가구 전체 무주택으로 추정하지 않음                                  |
| 가구 특성·소득·복지 여부 | 대상 가구, 산정 방식·연도·규모, 필수/대체 경로       | 중위소득 구간·모름·해당 없음 구분. 월급·가구 형태로 자동 환산 금지              |

정보 상태는 공통 계약의 `KNOWN`, `EXPLICIT_NO_RESTRICTION`, `EXPLICIT_NOT_APPLICABLE`, `MISSING`, `UNRESOLVED`를 따른다. 빈 값은 제한 없음, 아니요, 0으로 채우지 않는다.

검수된 조건에는 대상 인물·범위, 연산자·단위·경계·기준일, 근거, 공통 필수 AND, 대체 OR, 제외·예외와 완전성이 필요하다. 한 대체 경로가 불일치해도 다른 경로가 미확인이면 정책 전체를 제외하지 않는다.

아동 교육은 기존 자녀별 보육·교육 이용 현황, 자녀 정보와 가구 특성 질문을 재사용한다. 이 답변을 교육비·학습 지원의 자격 판정이나 검수된 세부 유형으로 자동 변환하지 않는다.

현재 화면에서 묻지 않는 조건은 추가 확인 사항으로 남긴다. 카테고리별 상세 질문 목록은 정책의 검수된 조건을 축적한 뒤 보완하며, 현재 질문에 맞추려고 원문의 조건을 생략하지 않는다.

## 8. 조회·정렬 적용 정책

아래는 후속 검색 적용 기준이며 현재 공개 UI의 동작이 아니다. 이번 구현 범위는 라벨 저장 자동화까지다.

### 1차: 분야 분류 적용

- 현재 활성 후보·공개 요건을 만족하고 선택 분야에 **유효한 VERIFIED 라벨**이 있는 정책만 해당 분야의 기본 결과로 조회한다.
- 분야가 미확정인 정책을 ‘정보가 부족하니 포함’이라는 이유로 모든 카테고리에 넣지 않는다. 원본은 보존하고 별도 검수 대기 건수로 관리한다.
- 분야는 확정됐지만 자격 정보가 부족한 정책은 결과에 남기고 ‘추가 확인 필요’로 표시한다. 분야 미확정과 자격 미확정을 구분한다.
- 결과가 적거나 없더라도 넓은 키워드 검색으로 자동 확장하지 않는다. 선택 분야 변경과 검수 범위 안내를 제공한다.
- 전체 대상 데이터에 필터를 적용한 뒤 중복 제거·건수 계산·페이지 나누기를 수행한다. 먼저 불러온 일부 목록만 필터링한 건수를 전체 결과 수로 표시하지 않는다.

### 2차: 세부 목적·조건 적용

- 세부 지원 목적이 확인되면 일치 정책을 우선 정렬한다. 미확인 유형은 ‘추가 확인 필요’로 분리하고 자동 탈락시키지 않는다.
- 검수된 조건으로 모든 대체 경로의 불일치가 확정될 때만 기본 결과에서 제외할 수 있다. 제외 근거를 내부 기록으로 남긴다.
- 입력 누락·모름, 거친 날짜/소득 구간, 원문 충돌·예외 미해결은 `NEEDS_CHECK`다.
- 모든 필수 조건과 예외를 비교할 수 있는 범위에서만 `MATCH`를 허용한다. 이 상태도 공식 신청 승인이나 지급 보장을 뜻하지 않는다.
- 접수 마감과 자격 불일치는 별도 상태다. 접수 상태가 미확인이면 ‘접수 중’으로 표시하지 않는다.

임의 점수나 모델 신뢰도만으로 숨기지 않는다. 초기 정렬은 ‘세부 목적 일치 → 확인이 필요한 정책’처럼 설명 가능한 그룹을 우선하고, 수치 가중치는 실제 표본 평가 뒤 별도 결정한다.

## 9. 검수 절차와 변경 관리

1. **표본 구성:** 기존 관련·검토·제외 후보에서 원본이 있는 표본을 선정한다. 6개 분야, 아동 본인 지원, 복수 분야, 복합 서비스, 부정문·동음이의어, 근거 부족 사례를 포함한다.
2. **자동 초안:** 분야·세부 유형·대상·근거 문장·보류 이유를 제안한다. 키워드만 출력하거나 근거 없는 빈 항목을 채우지 않는다.
3. **독립 검수:** 검수자가 원문과 제안을 대조한다. 초기 기준 표본은 두 검수자가 독립 판정하고, 불일치는 조정 담당자가 사유와 최종 기준을 기록한다.
4. **규칙 조정:** 합의된 경계 사례로 사전을 수정한다. 기준 변경에 사용한 표본과 최종 품질 평가 표본은 분리한다.
5. **일괄 라벨링:** 확정 사전으로 확대하되 검수 완료 범위만 검색 적용 후보로 둔다. 자동 초안의 대량 생성을 검수 완료로 집계하지 않는다.
6. **조회 전 대조:** 현재 조회 결과와 라벨 기반 결과를 비교하고, 새로 포함·제외되는 정책 및 이유를 검토한다.
7. **원본 갱신:** 스냅샷이나 의미 관련 필드가 달라지면 영향을 받는 라벨·규칙을 재검수한다. 영향 판단이 불가하면 STALE 처리한다.

검수 책임은 분류 작성자, 원문 검수자, 불일치 조정 담당자, 조회 적용 담당자로 나눈다. 실제 담당자는 착수 전에 지정한다. 자동 처리와 수동 수정 모두 버전·근거·사유를 남기고 과거 이력을 덮어쓰지 않는다.

사전 버전을 바꾸면 영향받는 분류와 기존 결과를 다시 평가한다. 문제가 생기면 이전 사전·검색 적용 버전으로 되돌릴 수 있어야 한다. 단, 변경된 원본에 무효한 옛 검수를 다시 유효하게 만들지는 않는다.

## 11. 1차 완료 기준과 평가

다음 수치는 **착수용 제안 목표**이며 실제 달성 수치가 아니다. 실제 분포와 검수 비용을 확인한 뒤 적용 버전에 기록해 확정한다.

현재 확보한 근거는 활성 후보 1,000건의 전수 AI 보조 검수, 로컬·원격 저장 검증 및 원격 활성화 자동 생성 검증이다. 독립 AI 표본 검수 125건에서 109건 일치·16건 차이를 확인했고, 공통 경계 보완을 포함한 20건의 조정 기록을 남겼다. 이 표본은 기준 조정에 사용했으므로 별도 최종 정확도 평가가 아니며, 아래 정밀도 95%·재현율 90% 목표 달성이나 인간 검수 완료로 해석하지 않는다.

- 기준 정립 표본은 최소 100건으로 시작하고, 각 카테고리의 긍정 사례를 최소 15건 확보한다. 복수 분야 표본의 중복 집계 여부를 함께 기록한다.
- 위 표본에 더해 오탐 위험·부정문·범위 밖 사례 최소 25건을 검수한다. 표본 크기가 작으면 비율만으로 전체 품질을 단정하지 않는다.
- 튜닝에 쓰지 않은 별도 평가 표본에서 분야별 정밀도·재현율과 혼동 사례를 보고한다. 초기 목표는 각각 95%·90%이며, 분모·실제 건수와 함께 평가한다.
- 정밀도는 ‘그 분야로 분류한 것 중 정답’, 재현율은 ‘정답 분야 정책 중 찾아낸 것’이다. 재현율 평가는 자동 분류 음성·검토·미분류를 포함해야 하며, 현재 결과에 나온 정책만 검수하지 않는다.
- 아동 본인 지원 누락, 임산물·창업보육 오탐, 양육·보육·돌봄·아동 교육 경계 혼동, 경로 간 조건 혼합 등 명시된 회귀 사례는 평가 표본에서 모두 통과해야 한다.
- 검색 적용할 VERIFIED 라벨은 근거·원본·사전 버전·검수 이력이 모두 연결되어야 한다. 분야별 전체 대상 수, 검수 완료 수, 미확정 수, 공개·검색 적용 가능 수를 별도로 보고한다.
- 표본 목표 통과만으로 미검수 전체 데이터를 공개하거나 조건 비교를 활성화하지 않는다. 부족한 분야는 적용 범위를 제한하고 그 범위를 기록한다.

조건 비교 도입은 별도 완료 기준을 둔다. 날짜·연령·소득 경계, 같은 자녀 결합, AND/OR·예외, 정보 부족, 접수 상태, 원본 변경의 사례를 검증한 뒤 비교 가능 범위만 공개한다.

## 12. 다음 실행 산출물

원문 검수·조정 기록과 로컬·원격 저장 검증 결과는 [실행 안내](./policy-labeling-runbook.md)에 정리했다. 후속 산출물은 다음과 같다.

1. 현재 후보 데이터의 분야별 표본 목록과 독립 검수 결과.
2. 근거 문장이 연결된 6개 카테고리·세부 유형 정답셋 및 경계 사례집.
3. 자동 분류 초안과 검수 결과의 차이, 사전 개정안.
4. 전체 라벨링·재검수 계획과 담당자, 공개·검색 적용 가능 범위 보고서.
5. 라벨 기반 조회 전후의 결과 차이와 되돌리기 계획.
6. 후속 자격 규칙 구조화와 분야별 질문 보완 목록.

검수 결과의 원격 저장은 사용자 승인 후 완료했으며, 전체 재실행과 활성화 트리거 검증에서도 누락·중복이 없었다. 라벨 기반 공개 조회와 자격 규칙 비교는 후속 구현으로 남긴다.
