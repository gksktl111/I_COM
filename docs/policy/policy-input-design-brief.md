# 정확한 정책 검색을 위한 입력 화면 요구사항

작성일: 2026-09-08 · 방향: 실제 정책 데이터가 요구하는 정보를 먼저 정하고 디자인에 반영한다.

근거는 [실제 저장 정책 8개 검증](./policy-data-fitness.md)이다. 아래 항목은 검색 비교에 필요한 입력 제안이며, 정책별 공식 기준 검수와 검색 구현은 아직 완료되지 않았다. 기존 Stitch의 항목 수·표현·예시 값에 맞춰 데이터 의미를 축소하지 않는다.

## 1. 두 단계 입력 흐름

사용자와 합의한 흐름은 **1단계 기본 정보·관심 정책 → 2단계 맞춤 상세 정보 → 추천 결과**다. 분석 로딩은 별도 입력 단계가 아니다.

- 1단계: 주민등록상 거주 지역, 가족 상황, 관심 정책 종류. 관심 종류는 복수 선택과 전체/잘 모르겠어요를 지원한다.
- 관심 종류의 초기 후보: 임신·출산, 양육·보육, 돌봄, 의료·건강, 주거·생활지원. 실제 API 분류를 확인하며 매핑하고 자격 조건과 구분한다.
- 2단계: 관련 정책에서 필요한 자녀 정보·가구 특성·소득 등 공통 상세 질문을 합쳐 한 번씩 묻는다. 정책별 추가 질문은 필요할 때 펼친다.
- 1단계의 임신·가족 상황과 2단계의 같은 답을 재사용한다. 미선택을 비해당으로 변환하지 않는다.
- 모름/건너뛰기를 허용하고 결과에서 누락 입력과 정책 자체의 미확인 기준을 구별한다.

아래 표는 두 단계에서 공유하는 입력의 의미 계약이며 모든 항목을 1단계에 배치한다는 뜻이 아니다.

### 공통 입력 항목

| 항목 | 화면에 필요한 구성 | 정확성 기준 |
| --- | --- | --- |
| 거주 지역 | 시도 → 시군구, 우선 주민등록상 주소지로 질문 | GPS와 구분. 실거주지가 다른 정책은 후속 질문. 상세 도로명 주소는 기본 입력에 불필요 |
| 가족 상황 | 임신 준비·임신 중·출산 후·자녀 양육을 복수 선택할 수 있는 흐름 | 임신 여부 예/아니요/모름·건너뛰기를 명확히 구분. 임신과 기존 자녀 양육은 동시 가능 |
| 가족·가구 특성 | 맞벌이, 한부모, 조손, 다문화, 위탁가정, 장애 관련 등 복수 선택과 모름·건너뛰기 | 특성 선택지는 코드 사전과 인정 기준 검수 후 확정. 한부모/조손은 구분하고, 체크 자체를 공식 자격 인정으로 보지 않음 |
| 자녀 정보 | 자녀별 생년월일(연·월·일), 자녀 추가·삭제, 총자녀 수 확인 | 월령은 기준일과 함께 계산. 모든 자녀를 입력했는지 확인하여 등록된 수를 총자녀 수로 잘못 사용하지 않음 |
| 소득 | 산정 기준 선택 + 해당 기준의 구간 + 모름·건너뛰기 | 기준 중위소득 비율과 저소득·차상위 인정 상태를 별도로 관리. 월급을 입력받아 자동 환산하지 않음 |

소득 구간의 구체적인 경계는 더 많은 정책 표본에서 확인한 임계값으로 결정한다. 현재는 아이돌봄비 원문에 150% 이하가 있으므로 이 경계를 구분할 수 있어야 한다. 가구원 수·기준 연도·산정 방식이 필요한 정책은 후속 확인한다. 잘 모르는 사용자가 임의의 소득 구간을 고르도록 강제하지 않는다.

정확한 생년월일을 제공하지 않는 경우 출생월·대략적인 연령으로도 탐색은 가능하게 하되, 경계 판정이 달라질 수 있으면 추가 확인으로 표시한다. 출생월만으로 임의의 1일을 생일로 채우지 않는다.

## 2. 관련 정책에서만 추가 질문

모든 사용자가 처음부터 아래 질문에 답할 필요는 없다. 후보 정책을 확인한 뒤, 판정에 영향을 주는 누락 항목과 그 이유를 보여준다.

| 후속 입력 | 필요한 실제 표본 | 질문의 범위 |
| --- | --- | --- |
| 부모·자녀의 해당 지역 주민등록 시작일 및 계속 거주 여부 | 중구 장애인가정 6개월, 중구 출산양육 1년 조건 | 해당 인물·지역·출산 기준일을 명시. 현재 주소만으로 과거 거주 기간을 충족 처리하지 않음 |
| 출산일·출생신고 여부·신청자와 아동의 관계 | 행복출산, 중구 출산 지원 | 생년월일에서 재사용 가능한 값은 중복 질문하지 않음. 산모·배우자·대리인 경로 구분 |
| 보육시설·유치원·종일제 돌봄 이용, 관련 지원 수혜 여부, 취학 여부 | 가정양육수당 | 각 자녀에 연결. 미이용·중복 제한을 임신/가족 태그로 대체하지 않음 |
| 위탁가정·연장보호 해당 여부 | 가정위탁 아동양육보조금 | 공식 인정 여부를 모르면 추가 확인. 자녀 연령 코드만으로 연장보호 대상 제외 금지 |
| 부 또는 모의 장애 등록 여부·정도 | 중구 장애인가정 출산지원금 | 정책에서 필요한 부모 관계와 인정 범위만 질문. 장애 진단 상세나 증빙 파일을 검색 단계에서 요구하지 않음 |
| 출생순위와 해당 정책의 산정 대상 자녀 | 중구 출산양육지원금 | 총자녀 수와 출생순위 분리. 산정 범위 미검수이면 수혜액 확정 금지 |
| 양육공백 사유·돌봄 방식·대상 영아 수·돌봄 시간·친족 관계 | 서울형 아이돌봄비 | 맞벌이 체크만으로 양육공백 인정 확정 금지. 친인척형/민간형 대체 경로 분리 |
| 지원을 찾는 대상자 관계·임신/출산 상태 | 위기임신·보호출산, 이주여성 건강관리 | 신청자가 직접 임신한 경우만 관련 정책으로 한정하지 않음. 산모·배우자·아동 등 경로 보존 |

임신 주수·출산 예정일·입양일 등은 향후 표본에서 비교에 필요하다고 확인된 경우에 추가한다. 현재 8개만으로 모든 사용자에게 이 항목이 필요하다고 확정하지 않는다.

## 3. 입력과 결과 화면의 공통 동작

- 최초 입력과 조건 수정 모달이 동일한 선택지·값·검증 방식을 사용한다.
- 명시적 ‘해당 없음’과 ‘모름/건너뛰기’를 구분한다. 선택하지 않은 항목을 자동으로 아니요로 저장하지 않는다.
- 추가 질문마다 ‘이 정보가 필요한 정책’과 ‘필요한 이유’를 간단히 표시한다. 미응답해도 정책 설명과 공식 출처를 볼 수 있다.
- 결과는 ‘입력 조건에 부합 / 추가 확인 필요 / 입력 조건과 불일치’로 구분하고, 각 판정의 근거와 미해결 조건을 표시한다.
- 일부 조건만 확인된 상태에 ‘100% 일치’, ‘지원 대상 확정’, 확정 지급액을 붙이지 않는다.
- 입력이 충분해도 정책 원본의 기준이 모호하면 ‘정책 기준 확인 필요’로 안내한다. 사용자의 추가 입력으로 해결할 수 없는 문제를 반복 질문하지 않는다.

## 4. 입력과 별도로 확보해야 하는 정책 데이터

정확도를 높이려면 입력 화면 개선과 함께 적용 지역·기준일·월령 경계·소득 산정 기준·대체 경로·예외·검수 근거가 필요하다. 현재 8개는 이런 규칙을 자동 비교할 구조와 검수가 완료되지 않았다.

따라서 다음 순서는 기본 입력 구조 정의 → 정책 원문 기반 규칙 후보·미해결 항목 정리 → 출처별 표본 검증과 공식 근거 보완 → 비교 기능 구현이다. 새 API 수집은 이 기준으로 작은 표본부터 병행할 수 있다.
