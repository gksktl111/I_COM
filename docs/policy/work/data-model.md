# 정책 공통 데이터·매핑 작업 기준

정리일: 2026-09-11. 출처가 다른 정책을 같은 의미로 다루기 위한 **논리 설계와 수용 기준**이다. 아래 필드·상태는 현재 DB 컬럼이나 API 응답을 확정하지 않는다. 구현된 수집·표시 저장은 [수집·저장 계약](ingestion-contract.md), 서비스 흐름·현재 상태는 [추천 구현 계획](recommendation-plan.md), 공개·자격·갱신 판단은 [정책 처리 기준](recommendation-engine.md)을 따른다.

## 공통 레코드와 근거

원본에 없는 값을 공통화 과정에서 채우지 않는다. 원본, 표시, 탐색 분류, 조건 후보, 검수 규칙은 별도 산출물로 연결한다. 사용자의 검색은 내부 데이터로 수행하며 검색 요청마다 외부 정책 API를 수집하지 않는다.

| 묶음 | 논리 표현 | 필수 의미 |
| --- | --- | --- |
| 정책 식별 | `policy_id` | 출처 간 동일 정책 검수 후 연결하는 내부 ID. 제목만으로 병합하지 않음 |
| 출처 식별 | `source_ref` | 제공자·외부 ID·API/데이터셋 버전. 외부 ID는 제공자 범위에서 해석, 미제공 버전은 미확인 |
| 원본 | `snapshot_ref`, 원본 해시·수집 시각·응답·완전성·오류 | 적용 목록/상세/조건을 재식별. 일부 응답 실패는 조건 없음이 아님 |
| 변환 | `mapping_version`, `normalization_version`, `rule_version` | 원본 갱신과 변환/규칙 변경 구분. 서로 다른 버전의 표시·규칙을 무검수 결합하지 않음 |
| 값 근거 | `evidence_refs[]` | 출처·스냅샷·원본 경로·근거 문장. 한 값에 복수 근거 허용 |
| 검수 | 상태·검수자·시각·범위·유효 기간·미해결 사유 | 후보/검수 완료/재검수 필요 구분. 수집 성공은 검수 완료가 아님 |

원본 제공자의 갱신 시각, 내부 수집 시각, 검수 시각을 분리한다. 선정기준이 비어 있어도 지원대상·지원내용에 조건 근거가 있을 수 있다. 변경 영향이 불명확하면 관련 규칙을 재검수하고 이전 규칙으로 확정하지 않는다.

## 표시·기관·링크

| 묶음 | 보존할 내용 |
| --- | --- |
| `display` | 공식 정책명, 요약, 지원대상, 선정기준·예외, 지원내용, 신청기한 원문, 신청방법, 서류·준비사항 |
| `organizations[]` | 소관·접수·문의 역할, 기관명과 제공된 연락처. 기관 소재지는 적용 지역과 별개 |
| `summary_review` | 제공자 요약/내부 작성 구분, 원문 대표성, 금액·대상·예외 누락과 원문 내부 충돌 |
| `links[]` | 공식 원본/온라인 신청/PDF/서류 발급 등 역할, 원문 URL, 확인 시각, 문법·공식성·접속·정책 일치·신청 경로 상태 |

숫자·단위·부정·예외·목록의 조건 관계는 HTML·공백 정리와 목록 축약 뒤에도 보존한다. 서류 누락과 원문의 ‘해당없음’은 다르다. 미확보 값은 화면에서 확인 필요로 안내할 수 있지만 실제 데이터로 만들어 저장하지 않는다.

공개 목록에는 공식 정책명·출처 있는 요약·주요 대상·지원내용·신청 기간 또는 관련 일정·소관 기관을 제공한다. 상세는 같은 정책 ID와 표시 버전을 사용해 대상·조건·지원내용 전체, 신청방법, 서류, 역할별 기관·연락처, 공식 출처와 확인 시점을 제공한다. 비교 결과·미해결 사항은 목록과 상세에서 동일한 평가를 사용한다. 표시와 규칙의 원본 버전이 다르면 확정 판정을 중단한다.

공식 원본과 신청 링크는 별개다. 문법 통과는 공식성·접속·신청 가능성을 뜻하지 않는다. 잘리거나 복수인 URL을 추측해 수정하지 않는다. 다른 공식 출처로 보완하면 확인 근거를 기록한다. 일시 접속 실패는 확인 시점과 함께 수동 확인 대상으로 남긴다. 공식 원본이 없는 정책은 원본을 보관하되 검수 기반 추천 공개는 보류한다. 현재 잠정 추천의 적용 범위는 정책 처리 기준을 따른다.

## 분류와 조건의 표현

`classification[]`은 주제·관련성 탐색용이다. 제공자 코드·사전 출처와 버전·내부 대응·검증 상태를 남긴다. 미지 코드와 Y/null을 자격 통과·탈락·무제한으로 바꾸지 않는다. 다자녀 태그에서 ‘2명 이상’을, 연령 코드에서 자녀 연령을 자동 생성하지 않는다.

`condition_candidates[]`는 근거 기반 후보이며 유효한 검수 `rules[]`만 확정 비교에 사용한다. 관계와 완전성의 상세 판정은 정책 처리 기준에 두고, 매핑에서는 다음 의미를 빠뜨리지 않는다.

| 요소 | 표현할 의미 |
| --- | --- |
| 범위 | 정책 전체/하위 서비스/급여 분기/신청 절차와 해당 ID. 하위 서비스 조건을 통합 서비스 전체로 확대하지 않음 |
| 대상·사건 | 신청자·수혜자·부모·자녀·가구원·대리인 및 관계, 임신·출산·산후·입양 등 사건 |
| 비교 | 속성·연산자·값·단위·경계 포함 여부·기준일·근거. 총자녀 수/대상 자녀 수/지원 인원/출생순위 분리 |
| 관계 | 공통 필수, AND, 대체 OR, 제외·예외, 동일 인물 결합 키. 서로 다른 자녀의 사실을 합치지 않음 |
| 완전성 | COMPLETE/PARTIAL/UNKNOWN, 범위·미해결 항목. 표현 못한 예외를 삭제해 COMPLETE로 만들지 않음 |

행복출산의 자녀 2명·만 25세 미만 안내는 철도 할인 하위 서비스에 연결한다. 가정위탁의 월령별 지급액은 급여 분기이며 전체 자격 연령 상한이 아니다. 대리 신청 요건을 수혜자 요건으로 대체하지 않는다. 사례는 [저장 데이터 감사](../records/data-fitness.md#policy-data-fitness)의 과거 근거이며 최신 공식 판정이 아니다.

## 정보 상태와 단위

각 값은 `value`, `information_state`, `evidence_refs`, `unresolved_reason`을 함께 갖는다. 값 존재와 검수 완료는 별개다.

| 상태 | 의미 |
| --- | --- |
| KNOWN | 원본에 값 있음. 검수 전에는 확정 비교 근거가 아님 |
| EXPLICIT_NO_RESTRICTION | 해당 대상·속성·범위의 제한 없음에 명시적 근거 있음 |
| EXPLICIT_NOT_APPLICABLE | 명시적 비해당. 제한 없음과 구분 |
| MISSING | 누락·미제공. false·0·무제한으로 변환하지 않음 |
| UNRESOLVED | 모호함·해석 불가·충돌. 원인과 필요한 확인 자료 기록 |

| 영역 | 반드시 분리·보존할 의미 |
| --- | --- |
| 지역 | 전국/특정 지역/미확인, 지역 ID·사전 버전·계층·하위 지역 포함 여부, 대상 인물, 주민등록/실거주, 계속 거주 기간·기준 사건. 기관 소재지나 시설 GPS로 대체 금지 |
| 시간 | 자격 기준일, 정책 적용 기간, 신청 기간, 소급 기한, 급여 기간, 거주 기간, 필요한 정밀도·시간대. 출생월에 임의의 1일을 채우지 않음 |
| 연령 | 대상 인물, 만 나이/월령, 양쪽 경계, 기준일·계산 방식. 부모 나이를 자녀에게 적용 금지, 일수/30으로 월령 확정 금지 |
| 소득 | 소득인정액/기준 중위소득 비율/보험료, 연도, 가구 규모, 금액/비율, 구간·경계. 월급 환산이나 모든 코드 Y를 무제한으로 처리 금지 |
| 급여 | 금액·통화·주기·횟수·대상·인원·상한/하한·분기. ‘1인당’은 총자녀 수가 아님. 상충 금액을 대표 금액으로 축약 금지 |

접수 OPEN/CLOSED/UNKNOWN은 자격과 독립적이다. 검증된 신청 일정과 판단 시각이 있어야 OPEN/CLOSED를 부여한다. ‘상시’·‘예산 소진 시’만으로 현재 접수 중이라고 단정하지 않는다.

답변 매핑은 속성＋대상＋산정 기준＋기준 시점을 키로 사용하며 `required_by[]`에 정책·경로·규칙·질문 이유를 연결한다. 최초 입력과 수정은 같은 코드·값·의미를 사용한다. 알려진 값·명시적 아니요/비해당·모름·건너뛰기·미질문, 자녀 목록 완전성·실제 총수를 구분한다. 세부 질문 흐름·종속 답변 처리는 추천 작업 문서에서 관리한다.

## 추가 화면 데이터의 경계

디자인의 정책명·금액·날짜·건수는 예시이며 데이터의 정답이 아니다. 다음 정보는 실제 출처와 연결되기 전 생성하거나 기능이 있는 것처럼 표시하지 않는다.

| 화면 정보 | 필요한 별도 근거 |
| --- | --- |
| 처리기간·지급일 | 신청기한과 다른 원문·단위·기준 사건 |
| 금액 높은순·본인부담 도표 | 현금/융자/감면, 월/연/일회, 자녀/가구당, 지원금/본인부담 구분. 동일 기준 비교 불가 시 정렬 보류 |
| 최근 등록·공개 건수 | 외부 등록일/최초 수집일/공개일 중 의미 명시. 실제 공개 범위 집계 |
| 검증 완료·최종 검증일 | 검수 주체·시점·범위. 수집일이나 내부 검수를 공식 기관 검증으로 표현 금지 |
| 신청·공고 PDF·서류 발급 | 역할별 실제 링크·문서 출처·검수 상태. 문서·절차 생성 금지 |
| 시설·정원·우선 예약 | 별도 시설·정원·예약 데이터와 검증된 정책-시설 연결 |
| 보관함·프로필·알림·FAQ | 별도 사용자 기능 또는 공식 근거 데이터 계약 |

로딩·안내의 ‘외부 API 실시간 대조’, 동기화 시각, ‘공식 검증 완료’는 실제 구현·관측 근거가 있어야 한다. 점수·100% 일치를 수급 확률이나 미검수 조건 충족으로 표현하지 않는다.

## 출처 충돌과 동일 정책 연결

출처별 스냅샷·값·차이·적용 연도·지역·서비스 범위를 유지한다. 같은 제목이나 최신 수집일만으로 병합·덮어쓰기하지 않는다. 동일 정책 연결과 필드별 우선 근거는 검수자·이유·시점·범위를 기록한 결정이어야 한다. 통합 신청과 개별 급여는 관계로 연결할 수 있지만 같은 정책으로 합치지 않는다.

충돌이 해소되기 전 해당 값은 UNRESOLVED로 두고 의존 판정을 보류한다. 출처별 유리한 조건을 섞어 새 자격 규칙을 만들지 않는다. 원문 내부 충돌도 같은 방식으로 추적한다.

## 출처별 매핑과 수용 기준

새 API마다 아래 표를 작성하고 작은 실제 표본으로 검증한다. 미지원 필드도 행을 남겨 MISSING과 사유를 기록한다.

| 제공자·API 버전 | 원본 경로·표본 스냅샷 | 공통 필드·의미·타입 | 대상·범위 | 단위·경계·기준일 | 빈 값·코드 의미 | 변환·사전 버전 | 근거·검수·충돌 | 사용 용도·미해결 조치 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 작성 대상 | 목록/상세/조건 | 표시/분류/조건 후보 | 인물·서비스·급여·신청 | 해당 없음도 명시 | 명시적 상태/누락 구분 | 무변환도 명시 | 문장·확인 담당 | 보관/표시/공개/비교별 판정 |

앞 단계 통과는 다음 단계 통과를 보장하지 않는다.

1. **원본·매핑:** 식별·스냅샷·완전성·오류·모든 경로가 추적되고 미지원·미지 코드·범위 표현 불가에 처리 방식이 있다.
2. **표시:** 실제 원본과 정제 결과의 숫자·단위·부정·예외·관계를 대조한다. 손실은 수정하거나 사용 보류하며 원본 부족·충돌과 구분한다.
3. **공개:** 필수 표시와 공식 원본을 확보하고 링크의 공식성·접속·정책 일치, 요약·금액 문제를 검수한다. 공개 결정·보류 이유는 정책 처리 기준에 따라 기록한다.
4. **조건 비교:** 현재 표시 원본에 연결된 유효한 검수 규칙·대상·범위·단위·기준일·대체 경로·완전성을 확인한다. 상태·집계는 ELIGIBLE/INELIGIBLE/UNKNOWN 계약을 따른다.
5. **확장:** 표시/공개/비교 가능 범위와 미해결 담당·조치를 별도로 기록하고 대량 정제·자동 추천 반영 범위를 결정한다. 새 출처·형식·조건 유형은 해당 범위를 다시 검증한다.

실제 저장값과 적용 원본을 다음 형식으로 대조한다. 독립적인 원본 대조와 같은 정제기 재실행의 일관성 검사는 서로 다른 증거다.

필수 대조에는 지역 계층과 기관 소재지, 가족 복수/결합 코드, 자녀 수 산정 범위·동일 인물·연령 기준, 임신/출산/산후 대상, 소득 기준·구간 경계, 명시적 상태와 누락, 신청/지원 기간, 공식 링크, 현재 원본·규칙 버전과 충돌을 포함한다. 표현 가능성 감사와 엔진의 경계값·AND/OR 동작 테스트는 분리한다.

표본별 미해결 처리와 용도별 가능 범위를 기록해야 감사가 완료된다. 일부 표본 통과는 전체 정책·다른 API의 적합성을 보장하지 않는다. 과거 8개 표본의 개별 근거·수치는 저장 데이터 감사에 보존하며 현재 카탈로그 상태로 재사용하지 않는다.
