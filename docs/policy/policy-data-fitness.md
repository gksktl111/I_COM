# 저장 정책의 검색 데이터 적합성 검증

검토일: 2026-09-08 KST · 대상: 개발 DB의 실제 적용 정책 8개 · 기준: [검색 요구사항 FR-06~10](./policy-search-requirements.md)

## 1. 결론

**현재 정제는 원문 표시를 위한 기반으로 적합하지만, 여섯 입력 조건으로 정책을 비교할 데이터 준비는 완료되지 않았다.** 8개 모두 검색 규칙의 추가 구조화·검수가 필요하다. 원본이 부족하거나 내부적으로 상충하는 항목도 있어, 구조화만으로 모든 정책을 확정 비교할 수는 없다.

- 저장된 표시 필드 112개(정책당 14개)는 매핑된 원본과 공백·줄바꿈 정리 외 차이가 없다. 이번 표본에서 숫자·단위·부정·예외의 정제 손실은 발견하지 못했다.
- 저장 원본을 현재 정제기로 재실행한 결과는 8/8 저장 결과와 같고, 원본 해시도 8/8 일치한다. 재실행 일치는 일관성 증거이며 의미 정확성을 단독으로 증명하지 않는다.
- 기본 목록 정보는 8/8 존재한다. 상세 선정기준은 4/8 null이지만 지원대상·지원내용 등에 조건이 있다. 선정기준 필드만 읽는 검색은 필요한 조건을 놓친다.
- 조건 비교 준비 완료는 0/8이다. 이는 정책이 사용자와 불일치한다는 뜻이 아니라, 유효한 검수 규칙이 아직 없다는 뜻이다.
- 공식 상세 URL은 8/8 저장돼 있고 문법 검증을 통과했다. 현재 접속 가능 여부·페이지 내용 일치·현행 정책 유효성은 이번 저장 데이터 감사에서 확인하지 않았다. 따라서 추천 공개 준비 완료로 판정하지 않는다.

## 2. 근거와 방법

[기계 대조 결과 및 저장 표시값](../fixtures/gov24/fitness/stored-audit.json)에 조회 시각, 정책별 적용 스냅샷 ID·원본 해시·수집 시각·정제 버전, 모든 필드의 대조 결과를 기록했다. 대상은 실제 원격 DB에서 source_id와 applied_snapshot_id를 함께 연결해 읽은 적용 원본이다. 외부 API를 새로 수집하거나 DB를 수정하지 않았다.

[오프라인 대조 스크립트](../../scripts/policy/audit-stored.ts)는 DB 내보내기 파일을 입력받는다. 원본 필드와의 독립적인 공백 정리 대조와 현재 정제기 재실행 대조를 분리했다. API·DB 인증키는 읽지 않는다.

```bash
node --experimental-strip-types scripts/policy/audit-stored.ts \
  .local/policy-sync/fitness/stored.json \
  /tmp/policy-stored-audit.json
```

DB 원본 내보내기는 Git 제외 로컬 파일이다. 커밋 가능한 근거 파일에는 공개 정책 설명·기관 문의처·식별자와 대조 결과만 포함한다. 지원대상·선정기준·지원내용·신청방법·신청기한과 지원조건 코드를 함께 검토했으며, 지역 4개 정책은 별도 검토자가 독립 대조했다. 아래 판단은 저장 스냅샷의 표현 가능성에 대한 검토이며 현행 법령 해석이나 공식 자격 검수가 아니다.

## 3. 판정 방법

각 항목은 다음처럼 구분한다. 한 항목에 구조화 필요와 정보 부족이 동시에 있을 수 있다.

| 표시 | 뜻 | 처리 |
| --- | --- | --- |
| 사용 가능 | 해당 용도의 정보와 의미가 보존됨 | 표시 또는 검수된 용도에서 사용 |
| 구조화 필요 | 원문에 근거가 있으나 비교 대상·범위·단위·관계 등의 내부 표현이 없음 | 근거와 연결한 규칙 후보 작성·검수 |
| 정보 부족 | 원본에 기준이 없거나, 모호하거나 상충함 | 미확인 유지, 공식 자료로 보완 |
| 정제 오류 | 원본의 의미가 정제 과정에서 손실·변형됨 | 수정 후 재정제·재검증 |

표에서 ‘언급 없음’은 조건이 없다는 확정이 아니다. 원본 코드의 Y/null도 조건 통과·탈락·무제한으로 바꾸지 않는다. 모든 정책은 현재 규칙 미검수이므로 아래 원문 근거만으로 MATCH/NO_MATCH를 생성할 수 없다.

## 4. 정책별 여섯 조건 대조

근거 경로는 별도 표시가 없으면 `raw.detail[0]`이다. 원문 인용은 저장 스냅샷 기준이다. 각 행의 현재 상태는 표시 텍스트 또는 원본 코드이며, 검색용 비교 규칙은 없다.

## 7. 조치와 완료 범위

- **완료:** 8개 정책 모두 여섯 조건과 목록·상세 필드 대조, 정제 일관성·공백 외 손실 검사, 정책별 부족 항목과 처리 방식 기록.
- **정제 오류 수정:** 이번 112개 표시 필드 대조에서 관찰된 손실이 없어 제품 코드·저장 데이터를 수정하지 않았다. 정보 부족을 임의 값으로 채우지 않았다.
- **구조화:** 위 6절을 다음 공통 매핑 계약에 적용한다. 근거 후보는 있어도 검수 전 규칙을 검색에 사용하지 않는다.
- **원본 부족·상충:** 공식 안내·사업 지침·정책 담당기관 자료로 보완하고, 확인 전 추가 확인 상태를 유지한다. 원문 부족의 해소는 이번 감사의 완료 범위가 아니다.
- **공개 전 확인:** 공식 링크 내용 일치, 잘림 의심 신청 URL, 금액·요약의 대표성, 현행 접수 상태는 별도 검수한다.

현재 표시 기반은 8개 모두 확보됐지만, 세부 공백·출처 확인이 남아 공개 가능 정책 수를 확정하지 않았다. 확정 조건 비교 가능 정책은 0개다. 다음 API의 **소규모 표본 수집과 매핑 검증**은 이 보완안을 기준으로 진행할 수 있다. 전체 정책 대량 정제와 자동 추천 반영은 출처별 표본 검증·규칙 검수 이후로 둔다.
