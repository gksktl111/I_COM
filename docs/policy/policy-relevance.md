# 정책 서비스 관련성 평가

기준일: 2026-09-08 · 평가 버전: `policy-relevance-3`

전체 정책을 서비스 관련성 검사 없이 저장하면서 어업 경영자금, 참전수당 등 육아·가족 서비스와 범위가 다른 정책이 섞였다. 필수값 충족률은 정제 누락 검사이므로 서비스 관련성을 대신할 수 없다.

## 아동 본인 지원 재검사 (v3)

2026-09-08 추가 수집을 멈춘 시점의 정책 2,277건을 재검사했다. 아동·청소년 본인 대상 지원이 부모·가족 표현 없이도 분류되도록 한다. 아동 상담·의료·급식·장학·문화·체육·생활 지원, 초중고 약칭과 명시적 아동 연령 경로를 인식한다. 법령 인용과 수급 자격 명칭만으로 아동을 추정하지 않으며, 실제 아동 대상 문장에서 법·수급·차상위라는 단어만으로 근거 전체를 버리지 않는다.

| 현재 정책 분류 | v2 | v3 반영 완료 |
| --- | ---: | ---: |
| 활성 | 734 | 842 |
| 검토 대기 | 952 | 845 |
| 제외 보관 | 591 | 590 |

검토 대기 105건과 기존 제외 4건을 관련으로 회수했다. 제외에서 회수하는 4건은 긴급돌봄의 아동 연령 경로, 북한이탈주민 정착금의 한부모 아동보호 가산금, 18세 이하 세대 건강보험료 지원, 국립수목원의 어린이·유아 관람료 경로를 원문으로 확인했다. 검토 2건과 기존 관련 1건은 명시적인 성인 전용 지원으로 제외했다.

문화·체육·일상생활 지원은 기존 아동 돌봄 분야에, 상담·심리·위생은 아동 의료·건강에 포함한다. 아동 제외 괄호 문구·일반 대학생·성인 자녀·산업/기업 지원·임산물·장례 안치료는 긍정 근거로 사용하지 않는다. 혼합 대상 사업은 실제 아동 지원 경로만 관련성 근거로 삼는다.

v3 회귀 검사 28개, 자동 수집·공통 저장·DB 통합 검사와 관리자 v1/v2/v3 표시 검사를 통과했다. 아동 상담 정책을 v2 검토에서 v3 활성으로 이동하면서 정제 원본·스냅샷·양쪽 평가 이력을 유지하는 DB 회귀 검사도 통과했다. 린트·TypeScript·프로덕션 빌드 통과. 실제 DB에서 정책 2,277건·원본 스냅샷 2,482건 보존, 평가 이력 3,532→5,809건, 현재 v3 평가 2,277건·입력과 연결되지 않은 평가 0건을 확인했다. 관리자 집계도 활성 842·검토 845건과 일치한다.

마이그레이션 `20260908091150_policy_relevance_v3.sql`은 기존 권한과 함수 계약을 유지하고 v3 저장을 허용한다. 보안 advisor는 새 객체 경고 없이 기존 공통 함수·Auth 설정 경고만 반환했다. 감사 보고서는 `.local/policy-sync/child-scope-v3-audit.json`, 재평가 직전 입력은 `.local/policy-sync/relevance-v2-before-child.json`에 보존한다.

## v2 초기 재분류 기록

초기 연속 수집을 중단한 뒤 개발 DB의 출처별 레코드 1,247건을 강화된 v2 기준으로 재평가했다. 출처 간 동일 정책 통합 건수나 공개 승인 건수가 아니다.

| 관련성 / 관리 상태 | v1 | v2 |
| --- | ---: | ---: |
| 관련 / 활성 후보 | 268 | 304 |
| 무관 / 제외 보관 | 15 | 591 |
| 검토 필요 / 검토 대기 | 964 | 352 |

검토 대기에서 572건을 제외하고, 실제 아동·가족 지원 근거가 있는 41건을 관련으로 회수했다. 기존 관련 중 임산물 지원 2건과 공영장례 2건은 제외하고 운전면허 교육 1건은 검토로 이동했다. 원본 삭제 없이 현재 분류와 버전별 평가 이력을 저장한다.

관리자 기본 목록은 활성 후보이며 검토·제외·전체 보관은 별도 필터로 조회한다. 관련 판정도 규칙 기반 후보 분류이며 공개 승인이나 신청 자격 판정이 아니다. 남은 352건은 주제·대상·지원 내용이 불충분하거나 상충해 자동 판정을 보류한 항목이다.

이전 215건에 대한 v1 결과(관련 74·무관 15·검토 126)는 초기 표본 평가 기록이다. 위 표는 1,247건 시점의 기록이다.

## 분류 기준

서비스 범위는 부부·부모의 지원뿐 아니라 아동·청소년 본인 대상 정책을 포함한다. 부모·가족 단어가 없어도 실제 아동 대상과 지원 내용이 확인되면 관련 후보로 분류한다. 소득·거주지·신청 자격의 충족 여부는 이 분류에서 판정하지 않는다.

분야는 임신·출산, 양육·보육, 아동 돌봄, 아동 의료·건강, 아동 교육, 가족 지원, 신혼·자녀가구 주거의 7개이며 복수 분류를 지원한다.

- 직접적인 사업명 또는 지원 대상과 실제 지원 내용의 교차 근거를 사용한다.
- 요약·목적의 배경 설명, 구비서류, 선정기준의 부수적 언급만으로 관련을 확정하지 않는다. 제외 문구와 제외 목록도 긍정 근거로 사용하지 않는다.
- `창업 보육실`은 육아 보육이 아니다. `자녀`라는 관계 표현만으로 아동 연령을 추정하지 않는다. 보호종료 청년의 과거 아동 경력도 현재 아동 대상의 증거로 사용하지 않는다.
- 일반 주거·생활비·의료 지원은 일괄 제외하지 않는다. 명시적인 신혼부부 지원 경로가 있는 복합 주거 사업은 관련 후보가 될 수 있다.
- 기업·창업·소상공인 금융, 산업·수출·광업, 농림축수산 생산시설·경영, 노인·보훈, 장례, 대학·대학원 학비, 일반 성인 취업·자립 정책은 사업명과 실제 지원 대상에 명시된 범위 밖 근거로 제외한다.
- 농어업인 보육·임산부 지원, 사업주 육아휴직 지원금처럼 신청 주체가 성인이어도 실제 가족 지원 경로가 있으면 보존한다.
- `임산물`을 임신·출산으로, 장례의 `안치료`를 의료의 `치료`로 인식하지 않는다. 아동 진료·입원과 초중고 교육·통학 근거는 관련 판정에 반영한다.

## 저장과 수집 연결

`policies.relevance`와 `relevance_assessed_at`은 현재 표시 데이터의 평가다. `policy_relevance_observations`는 원본 스냅샷·정제 버전·표시 해시·평가 버전에 묶인 이력이다. 저장 원본이나 정제 결과를 수정하지 않고 별도 평가를 추가한다.

`catalog_status`는 관련성 평가에서 DB가 자동 계산한다. 무관 정책을 별도 플래그로 활성화할 수 없으며, 원본 변경으로 평가가 무효화되면 자동으로 검토 대기로 돌아간다. 서버 전용 `policy_active_candidates` 뷰는 활성 후보만 반환한다. 기존 원본·정제 내용·평가 이력은 보존한다.

모든 실제 수집기의 공통 `createRepository()`가 `apply`에 평가 결과를 추가한다. DB에서는 정책 반영과 평가 이력을 같은 트랜잭션에 저장한다. 과거 스냅샷에 대한 늦은 재평가는 거절하며, 원본 또는 정제 결과가 바뀌면 이전 현재 평가는 해제한다. 같은 버전·같은 입력에 다른 평가를 덮어쓰지 않으므로 분류 규칙을 바꿀 때 평가 버전과 DB 허용 버전도 함께 올려야 한다.

신규 정책 수집에는 제외 단계를 적용했다. 자동 수집은 최신 목록의 정책명만으로 무관함이 명확하면 상세 API 호출과 정책 신규 저장을 생략한다. 목록만으로 애매하면 상세 원문을 확인하고, 상세 평가가 무관이면 신규 정책 목록에 반영하지 않는다. 검토 필요는 자동 제외하지 않고 저장해 보류한다. 공통 저장 경로도 무관한 새 정책의 반영을 차단하므로 선택형 수집에 적용된다.

목록 단계 제외는 이미 저장된 목록 페이지를, 상세 단계 제외는 수집된 원본 스냅샷을 보존한다. `policy_sync_items.scope_relevance`·`scope_phase`와 처리 이력에 제외 근거를 기록하며 재개 시 같은 제외 항목을 반복 처리하지 않는다. 처리 완료를 위한 내부 항목 상태는 SUCCESS지만 실행 요약과 관리자 표시는 저장 성공과 제외를 나눠 집계한다.

기존 정책은 삭제하거나 제목만 보고 갱신을 건너뛰지 않는다. 전체 상세를 다시 확인해 관련성 평가를 갱신한다. 따라서 기존 데이터 중 무관 591건은 감사용으로 보존되며, 서비스 사용 후보와 구분된다. 사용자 검색·추천은 아직 연결되지 않았으며 관련·검토·무관 상태를 반영해 연결해야 한다. 관련만 조회하는 관리자 필터는 공개 승인을 의미하지 않는다.

초기 연속 수집은 2026-09-08 17:24 KST에 종료했고 잠금 해제와 임시 상한 복구를 확인했다. 이후 새 실행에는 동일한 v2 제외 기준이 적용된다. 운영 예약은 활성화하지 않았다. 실행 기록은 [초기 후보 수집 기록](./policy-bulk-20260908.md)에 남긴다.

## 관리자와 재평가

`/admin/policies`에서 전체 기준 관련성 건수, 상태·분야 필터, 정책별 분류 이유·근거 필드·원문 문장·평가 시각·버전을 확인한다. 긴 근거는 화면에서만 줄이고 안내하며 저장 이력은 보존한다. 기술 품질 이력과 서비스 관련성은 별도다. 관리자 로그인 검증과 서버 전용 DB 권한을 유지한다. `/admin/collection`에는 실행별 저장 성공·제외 건수와 최근 제외 30건의 정책 ID·출처·목록/상세 단계·근거를 표시한다. 수동 판정 변경 기능은 이번 범위에 포함하지 않는다.

```bash
# DB 읽기와 로컬 보고서만 작성
node --experimental-strip-types scripts/policy/relevance.ts
# 현재 스냅샷을 다시 읽고 평가 이력 저장
POLICY_SYNC_ENABLED=true node --experimental-strip-types scripts/policy/relevance.ts --apply
```

로컬 감사 보고서는 `.local/policy-sync/relevance-report.json`에 비공개 권한으로 저장한다. 재실행은 이미 저장된 동일 버전 평가를 중복 추가하지 않는다.

## 검증

- 실제 1,247건을 읽기 평가해 전환 결과를 대조하고 DB 재평가를 완료했다. 기존 v1 보고서는 별도 보존했다.
- 분류 회귀 테스트 21개와 정책 테스트 파일 16개 통과. 관리자 데이터 테스트에서 인증 선행, 필터 검증, 안전한 근거 표시, 집계 응답을 확인했다.
- DB 회귀 검사: 반영·평가 원자성, 중복 방지, 오래된 평가 거절, 입력 변경 시 무효화, 이력 보존, 비관리자 역할의 테이블·함수 접근 거절.
- `npm run build -- --webpack` 통과(TypeScript 포함). 샌드박스의 분리된 TypeScript 자식 프로세스 출력이 비는 환경 문제를 확인하고 동일 빌드를 제한 밖에서 검증했다.
- 실제 DB 최종 대조: 정책 1,247건·원본 스냅샷 1,266건 보존, 관련성 이력 2,499건(v1 1,252 + v2 1,247), 현재 v2 평가 1,247건, 현재 입력과 연결되지 않은 평가 0건. 활성 후보 뷰 304건과 관리자 서버 API의 관련 304·무관 591·검토 352·미평가 0을 확인했다.
- DB advisor는 새 관련성 객체 경고 없이 기존 `rls_auto_enable` 실행 권한과 Auth 유출 비밀번호 보호 설정 경고를 반환했다. 이 작업에서 해당 공통 설정은 변경하지 않았다.

추가 제외 검증: 목록 단계 상세 호출 생략, 상세 단계 신규 정책 미반영·원본 보존, 검토 필요 저장, 기존 정책 갱신 유지, 출처 변경·오래된 실행 잠금·페이지 불일치 거절, 저장/제외 집계 분리, 관리자 제외 이력 접근 검사를 통과했다. `20260908075211_policy_scope_exclusion.sql`을 개발 DB에 적용했다.

기존 데이터 정리 마이그레이션: `20260908080358_policy_catalog_disposition.sql`. 활성 후보·검토·제외 전환, 분류 무효화 시 후보 제외, 원본·평가 이력 보존, 임의 활성화 거절 및 비관리자 뷰 접근 거절을 검증했다.

강화 기준 마이그레이션: `20260908082550_policy_relevance_v2.sql`. 기존 v1 이력·관리자 표시를 유지하면서 v2 저장을 허용한다. 기존 검토 정책을 v2로 제외할 때 양쪽 버전 이력과 원본을 보존하는 DB 회귀 검사를 통과했다.
