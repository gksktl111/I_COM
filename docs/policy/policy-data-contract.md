# Gov24 수집 데이터 계약 v1

2026-09-08. 근거: [실제 8개 표본 검증](./policy-api-validation.md). 중앙 4개·서울시 2개·서울 중구 2개를 두 번 수집했으며 각각 상세/지원조건 1행과 다음 빈 페이지를 확인했다. 이는 제공자의 전역 보장이 아닌 초기 고정 표본에 적용하는 보수적 내부 계약이다.

## 식별·완전성

- `서비스ID`는 공백 제거/숫자 변환 없이 정확히 일치하는 비어 있지 않은 문자열이다. 목록에서 선정 ID가 정확히 한 번, 상세와 조건에서 각각 한 번 나와야 한다.
- 매 실행 선정 시 사용한 목록 검색 조건을 처음 페이지부터 다시 순회한다. 목록 서비스ID 필터를 만들어 쓰지 않는다. 페이지별 `HTTP 200`, JSON 객체, 정수 건수, 요청 페이지·크기 일치, `currentCount=data.length`, 일관된 `matchCount/totalCount`, 누적 건수 일치와 끝의 빈 페이지를 요구한다. 중복 ID·건수 변화·페이지 상한·예산 소진은 미완료다.
- 상세/조건 0건 또는 복수 건, ID 불일치는 격리한다. 이번 표본에서 정상 조건 0건이 관찰되지 않았으므로 v1에서는 허용하지 않는다. 이후 별도 근거로 완화한다.
- 같은 수집 묶음의 세 응답만 결합한다. 기능별 조회시각과 페이지 메타데이터를 보존한다. 첫 목록 조회부터 마지막 조건 조회까지 10분을 넘으면 재수집한다. 10분은 내부 안전 한도이며 공급자의 동시 버전 보장이 아니다.
- 원본은 파싱된 JSON 전체 값이다. 누락/null/빈 문자열/0/false와 새 필드를 그대로 보존한다. 실패 원본은 정상 원본과 구별하고 표시 반영을 금지한다.

## 표시 필드

모든 텍스트 내부 타입은 `string | null`, 필수 이름은 비어 있지 않은 `string`이다. 원본에서 문자열·null·누락만 허용하며 숫자/객체 등을 문자열로 강제 변환하지 않는다. 빈 문자열·공백은 null, 원래 빈 값 종류는 `field_sources`에 기록한다. 같은 묶음 안에서도 자동 fallback은 하지 않는다.

| 내부 필드 | 원본 엔드포인트 / 필드 | 처리 |
| --- | --- | --- |
| name | serviceDetail / 서비스명 | 필수, 목록 이름과 불일치 시 격리 |
| summary | serviceList / 서비스목적요약 | 상세 목적과 별도 보관 |
| purpose_text | serviceDetail / 서비스목적 | nullable |
| target_text | serviceDetail / 지원대상 | 자격 해석 없음 |
| criteria_text | serviceDetail / 선정기준 | 자격 해석 없음 |
| benefit_text | serviceDetail / 지원내용 | 금액·단위·부정문 보존 |
| application_method_text | serviceDetail / 신청방법 | 표시 문장 |
| application_period_text | serviceDetail / 신청기한 | 기간/접수 상태 추정 없음 |
| required_documents_text | serviceDetail / 구비서류 | 표시 문장 |
| provider_name | serviceDetail / 소관기관명 | 적용 지역 추정 없음 |
| reception_text | serviceDetail / 접수기관명 | null은 과거 값으로 복원하지 않음 |
| contact_text | serviceDetail / 문의처 | 원문의 구분자 보존 |
| source_url | serviceList / 상세조회URL | 아래 URL 규칙 |
| application_url | serviceDetail / 온라인신청사이트URL | 아래 URL 규칙 |

HTML은 실제 파서로 처리한다. script/style을 버리고 문단·목록·br 경계를 줄바꿈으로 보존하며 엔티티를 해제한다. CRLF/CR을 LF로 통일하고 앞뒤 공백과 과도한 빈 줄을 정리한다. 원본의 숫자·단위·목록 번호를 재작성하지 않는다. HTML이 아닌 `<`, `>` 비교 표현도 보존한다. 원본 JSON은 수정하지 않는다.

URL은 원문과 `empty/valid/invalid` 상태를 별도 보관한다. 단일 절대 http/https URL이고 사용자정보·공백이 없어야 링크 값으로 허용한다. 복수 URL은 임의로 하나를 고르지 않는다. URL의 `valid`는 문법만 의미하며 실제 방문이나 신청 가능성을 보장하지 않는다. 서울형 아이돌봄비의 URL과 설명 속 URL 길이 차이는 경고로 보존하고 자동 복구하지 않는다.

각 표시 필드는 `field_sources`에 엔드포인트·원본 필드·빈 값 종류·fallback=false를 갖는다. 적용 스냅샷 FK를 통해 그 필드의 원본과 연결한다. 목록/상세 지원내용·신청방법은 요약/상세 차이가 있으므로 상세를 명시적으로 사용하고 차이를 경고에 남긴다.

## 날짜·조건

목록 `수정일시`는 14자리 달력 문자열, 상세는 `YYYY-MM-DD`로 관찰됐다. 각각 원문과 형식/달력 검증 상태를 저장하며 시간대를 추정해 UTC로 만들지 않는다. 동일 엔드포인트에서 유효한 동일 형식의 달력값이 이전 반영본보다 작아지면 원본 저장 후 표시 반영을 보류한다. 형식 미확인/변경도 자동 최신 판정을 보류한다. 목록/상세는 날짜 정밀도로만 차이를 관찰하며 서로의 값을 덮어쓰지 않는다.

지원조건은 Y/null, 연령 정수를 관찰했다. Boolean 변환·연령 주체/단위 추정·자격 규칙 생성은 하지 않는다. 신규 코드/값은 원본에 보존하고 UNKNOWN 경고로 남긴다. 응답 구조·ID는 여전히 검증한다.

## 해시·변경·재처리

SHA-256 입력의 JSON 객체 키는 재귀 정렬하고 배열 순서는 보존한다. 원본 해시는 apiVersion·externalId·목록 행·상세 배열·조건 배열·완전 상태를 포함한다. 조회시각·실행 ID·페이지 건수·재시도 횟수는 제외한다. 표시 해시는 실제 표시 값만 포함하고 조건 해시는 별도다. 해시/정규화 버전을 저장한다.

현재 반영본과 비교하여 무변경/원본만 변경/표시 변경/조건 변경을 구분한다. A→B→A는 A 스냅샷을 재사용하되 현재 B와의 반영 이력을 남긴다. 저장 원본 재정규화는 API를 호출하지 않고 같은 정규화 함수를 사용한다.

## 실행·오류

정책 하나가 원자적 반영 단위다. 원본 저장 성공 후 표시·근거 FK·변경 이력·항목 완료를 하나의 DB RPC에서 커밋한다. API 오류/정규화 실패/DB 오류가 난 정책의 기존 표시값은 유지한다. 누락 정책을 삭제하지 않는다. DB 임대 잠금은 소유자·세대·만료를 모든 쓰기에서 검증한다. dry-run은 읽기/조회/정규화만 하며 잠금과 실행 기록도 쓰지 않는다.

네트워크/5xx만 제한 재시도하며 총 호출 예산에 포함한다. 인증·권한·429는 해당 실행을 즉시 멈추고 다음 수동 실행으로 보류한다. 계정 한도/초기화는 미확인이므로 자동 스케줄을 아직 활성화하지 않는다. 운영 배포와 실제 12시간 간격 2회 성공 검증은 별도 완료 기준이다.
