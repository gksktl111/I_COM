# 추천 엔진 1차 구현

2026-09-09. 순수 TypeScript 엔진을 구현했다. 질문 UI·서버 API·실제 정책 탐색의 상세 모달을 연결했다. 실제 추천 공개 카탈로그는 검수 대기 중이며 비어 있다. 프로필·답변 영구 저장은 하지 않는다.

## 실행과 진입점

```bash
npm run policy:recommendation:test
```

진입점: `src/features/policy/recommendation/index.ts`의 `evaluateRecommendation(catalog, request)`.

```ts
import { evaluateRecommendation } from "../../src/features/policy/recommendation/index.ts";
import {
  educationFixture,
  educationRequest,
} from "../../src/features/policy/recommendation/education.fixture.ts";

// QUESTIONING: 추천 카드는 없고 다음 질문 또는 종료 사유를 반환한다.
const question = evaluateRecommendation(educationFixture, educationRequest);
// RESULTS: 동일 세션의 답변으로 최대 20개와 Top 5를 반환한다.
const results = evaluateRecommendation(educationFixture, {
  ...educationRequest,
  phase: "RESULTS",
});
```

E03·E04 fixture는 기존 사례에서 착안한 **단순화한 합성 테스트 데이터**다. 현실의 예외·최신 자격·접수 상태를 검증한 자료가 아니다. `FIXTURE` 공개·규칙 표시는 `PUBLIC` 모드에서 사용할 수 없다. 실제 서버 연결 시 mode와 catalog는 서버가 결정하며 사용자의 요청으로 FIXTURE 모드를 선택하게 하지 않는다. HUMAN 문자열 자체가 검수 증거는 아니므로 신뢰 가능한 서버 어댑터가 검수 기록·공개 버전에서 catalog를 구성해야 한다.

## 구현된 동작

- Fact의 속성·대상·산정 기준·시점을 정확히 비교한다. 미입력, 모름, 건너뜀, 상충, 범위 정밀도 부족을 UNKNOWN으로 보존한다.
- EQ·IN_SET·수치 구간·날짜 구간, AND/OR/NOT을 3값으로 평가한다. 불완전한 경로·오래된 규칙·검수되지 않은 규칙을 확정 자격으로 사용하지 않는다.
- 자녀별 경로를 독립 평가하고 가구 사실은 별도로 연결한다. 선택 목록 길이에서 총자녀 수·다자녀 산정 수를 만들지 않는다.
- 필요·시점·생애 단계·제공 방식·마감의 사전식 정렬을 사용한다. 근거 없는 금액 가점이나 자격 UNKNOWN 일괄 감점은 없다.
- 한 정책을 한 카드로 합치고 대표 경로의 상태·이유·순위 요소를 함께 유지한다. 자녀별 태그는 해당 자녀의 경로를 따로 집계한다.
- 필요 적합도가 같은 후보에서 자녀 편중과 목적 중복을 완화한다. 전체 정렬 후 최대 20개를 선택하며 Top 5는 그 앞의 최대 5개다.
- 질문의 가능한 등록 답변을 시뮬레이션해 영향 정책 수/부담으로 선택한다. 독립적인 복수 선행조건, 자녀별 선행조건, 가장 저렴한 후속 질문 부담, 이미 제공한 값의 정밀도 보완을 지원한다.
- 모름·건너뜀은 자동 재질문하지 않는다. 답변 변경은 `replaceAnswer`, 종속 사실 활성화는 `activateAnswers`로 처리하고 매 평가에서 전체 catalog를 다시 검토한다.
- QUESTIONING에서는 카드를 반환하지 않는다. 기본 5문항 묶음 한도에서는 QUESTION_LIMIT를 반환한다. 호출자가 계속 질문을 선택하면 묶음 카운터를 초기화하고, 마치기를 선택하면 RESULTS로 전환한다. 미확인 태그는 질문 종료 후에도 유지한다.

## 현재 경계와 다음 단계

- 이번 엔진은 검증된 카탈로그를 인자로 받는다. 서버 어댑터는 현재 공개 표시 데이터 조회와 fingerprint 비교를, UI는 revision 확인·이전 요청 취소·늦은 응답 폐기를 담당한다. 공개 승인 저장·원본 전체 버전의 의존성 검증·서명 커서는 후속 범위다.
- 질문은 등록된 선택지/구간을 사용한다. 원문 규칙에서 연속값의 모든 동치 구간을 자동 생성하거나 자유문 질문을 만들지 않는다. 새 규칙을 추가할 때 질문 구간의 충분성도 검수해야 한다.
- 정책 경로는 CHILD/HOUSEHOLD를 지원한다. 임신 사건·신청자와 보호자의 복합 역할 등 다른 5개 분야 확대용 바인딩은 후속 단계다.
- 입력 자녀는 최대 30명, 답변 300개다. 질문 하나의 시뮬레이션 평가가 4,096회를 넘으면 명시적 오류로 중단한다. 전체 카탈로그 운영 규모의 성능 보장은 아직 검증하지 않았다.
- 접수 상태는 입력 카탈로그의 근거 있는 상태를 사용하고 지난 마감은 CLOSED로 처리한다. 실제 신청 시작일·반복 모집·시점별 공개 유효성은 서버가 최신 평가 묶음에 반영해야 한다.
- 다음은 E03·E04의 현재 공식 근거와 예외를 보완하여 실제 검수 규칙과 현재 근거에 대한 인간 공개 결정을 등록하는 작업이다. 합성 fixture의 완전성 표시를 실제 정책에 복사하지 않는다.

## 검증

자격 모듈과 통합·질문 회귀 테스트 26개 통과. 자녀 정보 혼합 방지, UNKNOWN 유지, 실제 총자녀 수 미추론, 답변 수정으로 후보 복구, 공개 모드의 fixture 차단, 불완전 정책의 사용자 질문 방지, 20개/Top 5, 동률 내 자녀 균형, 복수 선행조건과 비용 순서 독립성을 검증했다. 전체 TypeScript 검사와 ESLint도 통과했다. 전체 Next.js 빌드는 앞선 작업에서 확인한 환경 오류(Turbopack 포트 생성 제한 및 대체 webpack의 TypeScript 설정 출력 해석 오류)로 완료되지 않았으며, 이번 순수 엔진 변경에서 같은 실패를 반복 실행하지 않았다.

## 질문형 UI 직접 테스트

개발 서버의 홈 ‘맞춤 진단 시작하기’는 **http://localhost:3000/policy/match**의 실제 서버 흐름으로 진입한다. 서버에 검수 완료된 추천 정책이 없으면 AWAITING_REVIEW를 받아 준비 중 안내와 실제 정책 탐색 링크를 보여준다. 이를 자격 탈락으로 표시하지 않는다.

합성 정책 2개의 질문·결과 체험은 **http://localhost:3000/policy/match/test**에서 제공한다. 이 페이지는 브라우저에서 순수 엔진을 호출하며 답변을 서버로 보내지 않는다. 실제 정책이나 최신 신청 기준으로 사용하지 않는다. 개발 서버는 127.0.0.1 대신 localhost를 사용한다.

정식 첫 화면은 현재 주민등록상 거주지(선택)와 6개 지원 분야(필수·단일 선택)다. 시·도 변경 시 구군을 초기화하고, 분야 변경 시 이전 분야의 필요·자녀 선택·상세 답변을 초기화한다. 다음 상세 단계는 선택 분야의 필요와 추천 대상을 받는다. 양육·보육/돌봄/아동 교육은 자녀 최소 한 명이 필수이며, 임신·출산/의료·건강/주거·생활지원은 자녀 관련 탐색을 선택적으로 추가한다. 자녀 입력은 기본 1명으로 시작하며 성별(남/여, 재선택 시 해제)과 출생연도를 받는다. 최대 30명까지 추가·삭제할 수 있고, 자녀 관련 진단에서 마지막 행까지 삭제하면 추가 전에는 질문 시작이 비활성화된다. 성별·연도 미입력은 미확인이며 출생연도를 정확한 생일·나이로 변환하지 않는다. 세부 필요는 분야별 선택적 복수 선택이며 교복·입학준비는 아동 교육에서만 표시한다. 합성 테스트 페이지의 범위만 교육 두 사례로 유지한다. 자녀 행 ID는 표시 순서와 분리해 삭제 후 재사용하지 않는다. 삭제한 자녀의 답변은 제거하며, 기본 정보를 수정한 자녀의 이전 상세 답변만 무효화하고 다른 자녀·가구 답변은 유지한다. 개별 Fact 질문은 하나를 선택하고 ‘선택한 답변으로 다음’으로 확정한다. 선택 항목을 다시 누르면 해제되며 미선택 상태에서는 다음 버튼이 비활성화된다. 모름·건너뜀·이전·5문항 묶음·최종 결과·수정·초기화를 지원한다. 선행조건이나 대상 변경으로 비활성화된 답변은 목록에 구분하고 현재 평가에서 제외한다.

실제 UI는 POST /api/policy-recommendations에 세션의 선택과 답변을 전송한다. 서버가 PUBLIC 모드와 평가 시각을 결정하며 클라이언트의 mode/evaluatedAt, 미등록 질문·선택지·대상, 불필요한 속성을 거부한다. 현재 주민등록 지역은 별도 residence 범위로 전송·검증한다. 이 값을 과거 기준일이나 실제 신청일의 자격 Fact로 복사하지 않으며, 실제 규칙과의 명시적인 의미 연결은 공개 카탈로그 구성 시 필요하다. 요청 본문은 128KiB로 제한하고 응답은 private/no-store다. 오류 후 재시도에 답변과 질문 정의를 유지한다. 네트워크 요청에는 20초 제한·취소·revision 검증이 적용된다.

recommendation-release.ts의 기본 공개 registry는 비어 있다. ACTIVE나 AI 분류를 HUMAN 공개 결정으로 승격하지 않는다. 검수된 catalog 주입 시 전체 표시 데이터 페이지를 읽고 fingerprint가 현재 데이터와 맞는 정책만 남긴다. 이 fingerprint는 공개 표시의 변경 감지이며 원본 전체의 검수 버전 증명은 아니다. 실제 공개 묶음의 검수 증거·유효성 등록은 여전히 필요하다.

실제 정책 목록 /policy의 제목·상세 버튼은 PolicyDetailModal을 연다. 독립 상세 URL도 유지한다. 모달은 실제 저장 표시값, 신청 방법·서류·문의·안전한 외부 링크를 보여주고 Escape/닫기/바깥 클릭·초점 복귀·배경 스크롤 잠금을 지원한다. 아코디언은 오른쪽 화살표와 키보드 접근을 제공한다.

결과 전환은 중앙 파동 3개가 0.45초 간격으로 퍼지는 약 2.2초 애니메이션이다. 실제 서버에서는 결과 응답이 도착한 뒤 전환 시간을 적용한다. 전환 중 결과 카드는 숨긴다. 움직임 줄이기 설정에서는 정적인 파동과 250ms 전환을 사용한다. 대기 중 입력 화면으로 돌아가면 요청과 타이머를 취소한다. 결과 폭은 최대 72rem이며 순위 리스트, Top 5 강조, 자녀별 상태·관심 일치·확인 사항 태그를 표시한다.
