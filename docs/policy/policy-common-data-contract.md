# 정책 API 공통 논리 데이터 계약 초안

작성일: 2026-09-08 · 상태: 수집·정제 설계를 위한 제안

다른 API를 연결하기 전에 출처가 달라도 같은 의미로 다룰 공통 필드를 정의한다. 근거는 [저장 데이터 적합성 검증 6절](./policy-data-fitness.md#6-공통-데이터-계약-보완안), [검색 요구사항](./policy-search-requirements.md), [입력 설계 요구사항](./policy-input-design-brief.md)이다. 아래 이름과 상태는 **논리 표현 제안이며 현재 DB 컬럼·API 응답·구현 완료를 뜻하지 않는다.** 현재 Gov24 구현은 [수집 계약](./policy-data-contract.md)과 [저장 계약](./policy-db-schema.md)을 따른다.

## 1. 공통 레코드와 근거

공통화는 원본에 없는 값을 채우는 작업이 아니다. 각 출처의 원본을 보존하고, 표시·분류·검수 규칙을 별도 산출물로 연결한다.

| 묶음 | 제안 필드와 의미 | 필수 처리 |
| --- | --- | --- |
| 정책 식별 | `policy_id`: 내부 공통 정책 ID | 출처 간 동일 정책 여부를 검수한 뒤 연결. 제목만으로 병합하지 않음 |
| 출처 식별 | `source_ref`: 제공자, 외부 ID, API·데이터셋 버전 | 외부 ID는 제공자 범위에서 해석. 미제공 버전은 미확인으로 기록 |
| 원본 | `snapshot_ref`, 원본 해시, 수집 시각, 목록·상세·조건 응답, 완전성, 오류 | 일부 응답 실패를 조건 없음으로 해석하지 않음. 적용 원본을 정확히 재식별할 수 있어야 함 |
| 변환 버전 | `mapping_version`, `normalization_version`, `rule_version` | 원본 갱신과 변환·규칙 변경을 구분. 서로 다른 버전의 표시와 규칙을 무검수 결합하지 않음 |
| 값의 근거 | `evidence_refs[]`: 출처·스냅샷·원본 경로·근거 문장 | 한 값에 복수 경로 허용. 선정기준이 비어 있어도 지원대상·지원내용의 근거를 연결 |
| 검수 | 상태, 검수자·시각, 검수 범위, 유효 기간, 미해결 사유 | 후보·검수 완료·재검수 필요를 구분. 수집 성공은 검수 완료가 아님 |

원본 제공자의 갱신 시각, 수집 시각, 내부 검수 시각은 서로 다른 필드다. 변경 영향이 불명확하면 관련 규칙을 재검수 대상으로 두며, 이전 규칙으로 확정 판정하지 않는다.

## 2. 표시와 출처 링크

| 표시 묶음 | 보존할 의미 |
| --- | --- |
| `display` | 공식 정책명, 요약, 지원대상, 선정기준·예외, 지원내용, 신청기한 원문, 신청방법, 서류·준비사항 |
| `organizations[]` | 소관·접수·문의 역할과 기관명·제공된 연락처. 기관 소재지는 적용 지역과 분리 |
| `summary_review` | 제공자 요약/내부 작성 구분, 원문 대표성, 금액·대상·예외 누락 및 원문 내부 충돌 상태 |
| `links[]` | 공식 원본/온라인 신청 등 역할, 원문 URL, 확인 시각, 문법·공식성·접속·정책 내용 일치·신청 경로 확인 상태 |

공백·HTML 정리 후에도 숫자, 단위, 부정, 예외, 목록의 조건 관계를 보존한다. 서류 누락과 원문의 ‘해당없음’을 구분한다. 잘린 URL을 추측해 복원하지 않으며 문법 통과만으로 공식성이나 신청 가능을 확정하지 않는다. 미확보 정보는 표시용 문구로 안내할 수 있지만 실제 값으로 만들어 저장하지 않는다.

## 3. 분류와 조건의 분리

`classification[]`은 관심 주제·관련성 탐색용이다. 제공자 코드, 코드 사전 출처·버전, 내부 분류 대응, 검증 상태를 남긴다. 미지 코드와 Y/null은 원본대로 보존하며 자격 통과·탈락·무제한으로 바꾸지 않는다. 다자녀 태그를 ‘2명 이상’ 규칙으로, 연령 코드를 자녀 연령으로 자동 변환하지 않는다.

`condition_candidates[]`는 원문 기반 후보이며, 검수된 `rules[]`만 확정 비교에 사용한다. 규칙은 다음 의미를 표현해야 한다.

| 요소 | 제안 표현·제약 |
| --- | --- |
| 적용 범위 | `scope`: 정책 전체 / 하위 서비스 / 급여 분기 / 신청 절차와 해당 ID. 하위 서비스 조건을 상위 통합 서비스 전체로 확장 금지 |
| 대상·사건 | `subject_ref`: 신청자·수혜자·부모·자녀·가구원·대리인과 관계. `event_ref`: 임신·출산·산후·입양 등 별도 사건 |
| 비교 | 속성, 연산자, 값·단위, 경계 포함 여부, 기준일, 근거. 총자녀 수·대상 자녀 수·지원 인원·출생순위는 별도 속성 |
| 조건 관계 | 공통 필수 조건, AND 묶음, 대체 OR 경로, 제외·예외, 동일 인물 결합 키. 서로 다른 자녀의 결과를 한 자녀의 충족으로 합치지 않음 |
| 완전성 | `COMPLETE / PARTIAL / UNKNOWN`과 범위·미해결 항목. 표현 못한 예외를 삭제하고 COMPLETE로 표시하지 않음 |

예를 들어 행복출산의 자녀 2명·만 25세 미만 안내는 해당 철도 할인 하위 서비스에 연결한다. 가정위탁 지원의 월령별 금액은 급여 분기이며 이를 전체 자격 연령 상한으로 바꾸지 않는다. 대리 신청 요건은 수혜자 요건과 별도로 둔다.

## 4. 정보 상태·지역·시간·단위

각 정규화 값은 `value`, `information_state`, `evidence_refs`, `unresolved_reason`을 함께 표현한다. 값의 존재와 검수 완료는 별개다.

| 정보 상태 제안 | 의미 |
| --- | --- |
| `KNOWN` | 원본에 값이 있음. 검수 전에는 확정 비교 근거가 아님 |
| `EXPLICIT_NO_RESTRICTION` | 해당 대상·속성·범위에 제한이 없다는 명시적 근거 있음 |
| `EXPLICIT_NOT_APPLICABLE` | 원본에 명시적 비해당. 제한 없음과 구분 |
| `MISSING` | 누락·미제공. 무제한·false·0으로 변환 금지 |
| `UNRESOLVED` | 모호함·해석 불가·출처 충돌. 원인과 필요한 확인 자료 기록 |

- **지역:** 전국/특정 지역/미확인, 지역 ID·코드 사전 버전·계층·하위 지역 포함 여부, 대상 인물, 주민등록지/실거주지, 계속 거주 기간과 기준 사건을 표현한다. 중앙기관이라고 전국, 서울 기관이라고 서울 거주 필수로 추정하지 않는다.
- **시간:** 자격 기준일, 정책 적용 기간, 신청 기간, 소급 기한, 급여 기간, 거주 기간을 구분한다. 날짜 정밀도와 시간대가 필요한 경우 함께 기록한다. 출생월만 있을 때 임의의 1일을 채우지 않는다.
- **연령:** 대상 인물, 만 나이/월령 등 단위, 양쪽 경계, 계산 기준일·방식을 보존한다. 부모 연령을 자녀에게 적용하거나 일수를 30으로 나눠 월령을 확정하지 않는다. 미확인 기준일은 미해결이다.
- **소득:** 소득인정액·기준 중위소득 비율·보험료 등 산정 기준, 연도, 가구 규모, 금액/비율 단위, 구간과 경계를 분리한다. 월급을 중위소득 비율로 추정하거나 모든 소득 코드 Y를 무제한으로 해석하지 않는다.
- **급여:** 금액·통화·주기·횟수·지급 대상·인원·상한/하한과 분기를 보존한다. ‘1인당’은 총자녀 수 조건이 아니다. 상충하는 금액은 단일 대표 금액으로 축약하지 않는다.

접수 상태 `OPEN / CLOSED / UNKNOWN`은 자격 비교와 독립적이다. 검증된 신청 일정과 판단 시각이 있어야 OPEN/CLOSED를 부여한다. ‘상시’나 ‘예산 소진 시’만으로 현재 접수 중이라고 단정하지 않는다.

## 5. 두 단계 입력과 공유 질문에 연결

사용자가 수용한 흐름은 **1단계 기본 정보·관심 선택 → 2단계 관련 상세 정보**다. 이는 입력 데이터 연결 원칙이며 이 문서에서 UI 코드나 화면을 구현하지 않는다. 관심 선택은 분류 탐색에 쓰며 법적 자격 인정으로 취급하지 않는다.

상세 질문은 후보 정책의 검수된 조건이 요구하는 미입력 정보에서 도출한다. 공통 질문은 `attribute + subject_ref + 산정 기준 + 기준 시점`이 같을 때 하나로 모으고 `required_by[]`에 필요한 정책·하위 서비스·규칙과 이유를 연결한다. 같은 자녀의 생년월일 등 이미 받은 값은 재사용한다. 주민등록지와 실거주지, 총자녀 수와 출생순위처럼 의미가 다르면 같은 질문으로 합치지 않는다.

답변은 알려진 값·명시적 아니요/해당 없음·모름·건너뛰기를 구분한다. 자녀 목록은 전체 입력 여부를 함께 표현하고, 불완전한 목록 길이를 총자녀 수로 쓰지 않는다. 정책 원문이 모호한 경우에는 사용자 질문을 반복하지 않고 정책 기준 확인 과제로 남긴다. 초기 입력과 조건 수정은 동일한 데이터 의미를 사용하며, 영구 저장 여부는 별도 요구사항이다.

## 6. 출처 충돌과 동일 정책 연결

출처별 스냅샷·값·차이·적용 연도·지역·서비스 범위를 유지한다. 동일 제목이나 최신 수집일만으로 병합·덮어쓰기하지 않는다. 동일 정책 연결과 필드별 우선 근거는 검수자·이유·시점·적용 범위를 기록한 결정이어야 한다. 통합 신청 서비스와 개별 급여는 필요하면 관계로 연결하며 같은 정책으로 합치지 않는다.

충돌이 해소되기 전에는 해당 값을 UNRESOLVED로 두고 그 값에 의존한 확정 판정을 보류한다. 서로 다른 출처의 유리한 조건을 섞어 새로운 자격 규칙을 만들지 않는다. 원문 내부 충돌도 같은 방식으로 추적한다.

## 7. 출처별 매핑 템플릿과 수용 기준

새 API는 아래 표를 필드별로 작성하고 작은 실제 표본으로 검증한다. API 미지원 항목도 행을 남겨 MISSING과 사유를 기록한다.

| 제공자·API 버전 | 원본 경로·표본 스냅샷 | 공통 필드·의미·타입 | 대상·범위 | 단위·경계·기준일 | 빈 값·코드 의미 | 변환·사전 버전 | 근거·검수·충돌 | 사용 가능 용도·미해결 조치 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 작성 대상 | 목록/상세/조건 경로 | 표시/분류/조건 후보 구분 | 인물·서비스·급여·신청 | 해당 없음도 명시 | 누락과 명시적 상태 구별 | 무변환도 명시 | 원본 문장·확인 담당 | 보관/표시/공개/비교별 판정 |

단계별 통과는 따로 기록한다. 앞 단계의 통과가 다음 단계의 통과를 보장하지 않는다.

1. **원본·매핑:** 식별·스냅샷·완전성·오류와 모든 매핑 경로를 추적할 수 있다. 미지원·미지 코드·범위 표현 불가 사례에 처리 방식이 있다.
2. **표시 정제:** 실제 표본에서 숫자·단위·부정·예외·관계의 보존을 대조한다. 손실은 수정하거나 해당 사용을 보류한다. 누락과 원문 충돌을 정제 오류와 분리한다.
3. **추천 공개:** 필수 표시 정보와 해당 정책의 공식 원본을 확보하고 링크의 공식성·정책 일치·접속 확인 및 요약·금액의 미해결 사항을 검수한다. 공개 보류 이유를 기록한다.
4. **조건 비교:** 현재 표시 원본과 연결된 유효한 검수 규칙, 대상·범위·단위·기준일·대체 경로·완전성을 확인한다. MATCH는 완전한 범위의 필수 조건 통과일 때만 허용한다. NO_MATCH는 유효한 필수 조건으로 모든 대체 경로의 불일치가 확정될 때만 허용하고, 그 외 미확인은 NEEDS_CHECK로 남긴다.
5. **확장:** 출처별 표본 결과에 표시 가능·공개 가능·비교 가능 범위와 미해결 담당·조치를 각각 기록한 뒤 대량 정제·자동 추천 반영 범위를 결정한다. 새 출처·형식·조건 유형은 해당 범위를 다시 검증한다.

현재 8개 정책은 표시 기반을 확보했지만 확정 조건 비교 가능 정책은 0개다. 이 초안 작성으로 그 상태가 바뀌지는 않는다. 지역 코드 사전, 출처별 매핑, 검수 담당·갱신 주기, 공식 근거 보완과 동일 정책 연결 결정은 후속 작업으로 남는다.
