# 맞춤 정책 추천 v1: 정책 처리 결정

작성일: 2026-09-09 · 상태: v1 설계 결정 · 구현·현행 공식 내용 검증·공개 승인 미완료

## 1. 목적과 문서 권한

이 문서는 정책을 추천 가능한 자료로 만드는 단위, 검수, 공개, 조건 판정과 갱신 처리를 결정한다.
질문 선택과 추천 순위의 실행 절차는 [적응형 추천 구현 설계](./policy-adaptive-recommendation-design.md)를 따른다.
두 문서는 **추천 v1의 목표 동작**을 정하며, 이 문서 작성으로 기존 데이터나 공개 동작을 변경하지 않는다.

- 원본·정보 상태·근거 보존은 [공통 논리 데이터 계약](./policy-common-data-contract.md)을 따른다.
- 기존 6개 분야의 의미는 [라벨링 기준](./policy-labeling-standard.md)을 유지한다.
- [입력 대응표](./policy-recommendation-input-mapping.md)의 필드 대응은 재사용한다. 그 문서의 초기 순위 제안은 이 두 v1 결정으로 구체화한다.
- [교육 20건 분석](./policy-education-mapping-audit-20260909.md)은 보존 자료의 설계 사례다. 현재 공식 자격이나 운영 승인 근거가 아니다.
- 기존 수집·저장·실행 안내의 현재 구현 사실은 그대로 유효하다. 추천 목표와 충돌할 때 현재 기능이 이미 바뀌었다고 해석하지 않는다.

이 문서의 상태명과 필드는 논리 계약이다. DB 컬럼, 마이그레이션 SQL, API 구현을 확정하거나 배포하는 작업은 포함하지 않는다.
공개 승인 대기는 정책 콘텐츠 검수의 생명주기이며, 사용자 로그인이나 대화 중 권한 확인 절차가 아니다.

## 2. 정책을 나누는 단위

처리 구조는 **정책 → 지원 경로 → 수혜자·사건 → 조건 묶음·급여 분기**로 고정한다.
정책 카드의 표시 단위와 실제 조건 비교 단위를 구분한다.

| 단위 | 반드시 연결할 정보 | 경계 |
| --- | --- | --- |
| 정책 | 내부 ID, 출처 ID, 표시 내용, 공식 링크, 원본 버전 | 같은 제목만으로 서로 다른 지역 사업을 병합하지 않음 |
| 지원 경로 | 안정적인 경로 ID, 실제 서비스, 분야, 세부 목적, 신청·이용 경로 | 통합 신청 서비스와 개별 급여를 구분 |
| 수혜자·사건 | 신청자·수혜자·대리인·가구 역할, 인물 ID, 입학·출산 등 사건 ID | 부모 조건을 자녀 조건으로 대체하지 않음 |
| 조건 묶음 | 공통 필수, AND, 대체 OR, 제외·예외, 기준일, 완전성 | 서로 다른 자녀의 충족 조건을 합치지 않음 |
| 급여 분기 | 금액·주기·인원·상한, 적용 조건, 해당 경로 | 금액 구간을 정책 전체 자격 상한으로 확대하지 않음 |

한 정책에 복수 경로·분야·목적을 허용한다. 결과 카드에서는 같은 정책을 합치되 추천 이유와 판정된 경로를 명시한다.
경로 하나를 확인했다고 다른 급여까지 받을 수 있다고 표시하지 않는다.
수혜자가 기관인 사업도 원본으로 보존하지만, 가족이 직접 신청하거나 실제 이용할 수 있는 경로가 없으면 가족 추천에 넣지 않는다.

## 3. 6개 분야와 세부 목적

상위 분야는 임신·출산, 양육·보육, 돌봄, 의료·건강, 아동 교육, 주거·생활지원으로 유지한다.
기존 분야·세부 유형 라벨과 별도로 **사용자의 필요에 대응하는 세부 목적**을 지원 경로에 연결한다.
교육의 교복·입학준비·통학·학습처럼 기존 세부 유형 하나로 구분하기 어려운 실제 지원을 표현하기 위해서다.

| 정보 | 사용 | 확정 근거 |
| --- | --- | --- |
| 분야 | 사용자가 선택한 분야의 후보 탐색 | 실제 지원내용·대상·선정기준의 해당 경로 |
| 기존 세부 유형 | 분류 사전의 세분화·검수 호환 | 해당 유형의 기존 정의 |
| 세부 목적 | 직접 선택한 필요와 비교 | 해당 경로에서 실제 제공하는 지원 |
| 생애 단계·가족 상황 | 관련성·순위 보조 | 사건·대상 연결과 사용자 답변 |
| 법적·사업상 조건 | 자격 비교 | 현재 유효한 인간 검수 규칙 |

세부 목적은 별도 버전의 사전과 분야·세부 유형 대응표로 관리한다. 기존 라벨과 일대일 대응을 가정하지 않는다.
명확하지만 사전에 없는 목적은 확장 검토 대상으로 남기며, 미확인을 임의의 `other`로 채우지 않는다.
사전 밖·서비스 범위 밖·근거 부족은 서로 다른 사유다. 미분류를 사용자 자격 탈락으로 표현하지 않는다.

## 4. 원본부터 공개까지의 산출물

각 단계는 독립 상태와 근거를 가진다. 앞 단계의 통과는 다음 단계의 승인이 아니다.

| 단계 | 산출물 | 완료·다음 행동 |
| --- | --- | --- |
| 수집 | 원본 응답, 출처, 스냅샷 ID·해시, 수집 시각, 오류·완전성 | 일부 응답 실패를 표시하고 원본 유지 |
| 정규화 | 정제값·해시, 정제 버전, 필드별 원본 경로 | 숫자·단위·부정·예외·관계의 보존 확인 |
| AI 후보 생성 | 분야·목적·대상·규칙 후보, 인용, 모델·프롬프트 버전 | 검수 목록에 등록; 추천 실행 규칙으로 사용 금지 |
| 인간 의미 검수 | 경로·분류·목적의 판단, 근거, 검수자·시각 | 모호함·충돌은 보류하고 보완 자료 지정 |
| 공개 결정 | 공개할 경로·표시·목적 범위와 현재 버전에 결박한 HUMAN 결정 | 공식 근거·표시 품질·가족 이용 가능성 검토 |
| 규칙 승인 | HUMAN 검수 규칙, 범위별 완전성·예외·의존성 | 승인된 현재 범위만 확정 비교에 사용 |
| 추천 제공 | 공개 경로, 판정 범위·이유·미확인 원인 | 서버에서 동일한 유효성 기준으로 재계산 |

원본 제공자 갱신 시각, 내부 수집 시각, 검수 시각을 별도로 보존한다.
검수 결정에는 스냅샷 ID·원본 해시·정제값 해시·정제 버전·분류 사전 버전·목적 사전 버전과 적용 범위를 연결한다.
규칙 승인에는 규칙 버전·기준 연도·의존 근거·유효 범위도 연결한다. 없는 버전을 만들어 채우지 않는다.
공식 링크는 URL 문법뿐 아니라 공식성·정책 일치·접속과 필요한 신청 경로를 확인한다.

## 5. 공개 결정과 규칙 승인의 분리

**2026-09-09 사용자 결정에 따른 현행 예외:** `/policy/match`에서는 기존 활성 공개 정책을 문구 관련도에 기반한 **잠정 추천**으로 제공한다. 아래 HUMAN 공개 규칙은 검수된 자격 판단 경로에 적용한다. 잠정 추천은 HUMAN 상태를 생성하지 않으며, 지원 대상·접수 가능 여부를 확정하지 않는다. 전부 추가 확인 태그와 공식 확인 안내를 제공한다. 이는 정책 수집이나 DB 상태 변경을 뜻하지 않는다.


v1 추천 공개 경로에는 **현재 자료에 대한 HUMAN 공개 결정**이 필수다.
보존된 `AI_ASSISTED`의 `VERIFIED`만으로 공개하거나 조건을 확정 비교하지 않는다.
기존 AI 검수 이력은 후보와 검토 근거로 보존하고 인간 검수로 바꾸어 기록하지 않는다.
인간은 공개 결정을 내릴 때 해당 분야·목적·수혜 경로의 의미를 확인해야 한다.

| 논리 공개 상태 | 의미 | 추천 행동 |
| --- | --- | --- |
| 검수 대기 | AI 후보 또는 인간 결정 미완료 | 내부 검수 목록에 유지 |
| 공개 보류 | 공식 근거·표시·대상·충돌 등의 해결 필요 | 해당 경로 추천 중단, 담당·해결 조건 기록 |
| 공개 가능 | 현재 근거와 버전에 맞는 HUMAN 결정 유효 | 다른 탐색 관문과 규칙 상태 평가 |
| 재검수 필요 | 공개 결정의 관련 의존성이 변경·만료 | 영향 범위 추천 중단 후 재검수 |
| 공개 철회 | 잘못된 공개 또는 더 이상 유효하지 않음 | 즉시 해당 범위 제외, 이력 보존 |

공개 가능은 신청 가능·접수 중·지급 보장과 다르다.
필수 표시·공식 근거·분야·목적·수혜 경로가 확인되어도 조건 규칙이 불완전할 수 있다.
그 경로는 공개 결정이 허용한 범위에서 `UNKNOWN`으로 안내할 수 있으며, 미확인 조건을 숨기지 않는다.
반대로 규칙이 완전해도 공개 결정이 없으면 v1 공개 추천에 포함하지 않는다.

## 6. 탐색 관문과 자격 제외

추천 처리에서는 먼저 공개·분야·서비스 범위를 확인하고, 그다음 자격을 판정한다.
**자격 판정 계층에서 후보를 제외하는 상태는 `INELIGIBLE`뿐**이다.
이는 공개가 철회되거나 분야가 맞지 않는 정책까지 반드시 보여야 한다는 뜻이 아니다.

| 관문·상태 | 처리 | 사용자 자격으로 해석 가능한가 |
| --- | --- | --- |
| 공개 근거 또는 HUMAN 결정 무효 | 해당 공개 범위 추천 중단 | 아니요 |
| 선택 분야의 현재 라벨 없음·STALE | 해당 분야 기본 추천 제외, 재검수 | 아니요 |
| 가족 신청·이용 경로 없음 | 가족 추천 범위 제외 | 아니요 |
| 세부 목적 불일치·미확인 | 순위·설명에 반영 | 아니요 |
| 규칙 불완전·오래됨·답변 미확인 | `UNKNOWN`으로 유지 | 탈락으로 해석 금지 |
| 유효한 규칙으로 전 범위 불일치 확정 | `INELIGIBLE`, 기본 현재 추천에서 제외 | 명시한 판정 범위에 한함 |

## 7. 세 가지 자격 상태와 완전성

공개 명칭은 `ELIGIBLE / INELIGIBLE / UNKNOWN`으로 고정한다.
기존 문서의 `MATCH / NO_MATCH / NEEDS_CHECK`와 각각 대응하며, 현재 코드에 이 열거형이 있다는 뜻은 아니다.
`ELIGIBLE`은 검수된 범위의 조건 충족 안내이고 공식 신청 승인이나 선정 확정이 아니다.

| 상태 | 필요한 증명 | 금지하는 해석 |
| --- | --- | --- |
| `ELIGIBLE` | 동일 수혜자·사건의 하나 이상 완전한 경로에서 공통 필수·AND·적용 예외를 모두 충족 | 연령 하나만 맞음, 일부 조건만 검수됨, 서로 다른 자녀의 조건 합산 |
| `INELIGIBLE` | 판정 범위의 모든 대체 경로·가능 수혜자를 검토하여 불일치를 확정하고 이를 뒤집을 예외도 해결 | OR 하나만 불일치, 미입력 자녀를 포함하지 않은 채 가구 전체 탈락 |
| `UNKNOWN` | 위 두 상태를 증명하지 못함 | 근거 없음·답변 없음·충돌을 false 또는 무제한으로 치환 |

완전성은 `COMPLETE / PARTIAL / UNKNOWN`으로 경로·규칙 묶음에 기록한다.
완전한 한 경로가 통과하면 그 경로의 `ELIGIBLE`을 정책 카드에 표시할 수 있다. 다른 경로는 별도 상태를 유지한다.
부분 규칙의 긍정 결과는 전체 `ELIGIBLE`로 올리지 않는다.
특정 경로에서 검수된 필수 조건의 실패를 확인하더라도 예외·대체 경로가 남으면 정책 전체는 `UNKNOWN`이다.
수혜 자녀를 명시하면 그 자녀 범위를 판정한다. 가구 전체 판정은 가능한 대상과 목록 완전성을 함께 확인한다.
자녀 목록이 불완전한 상태에서 입력된 자녀가 모두 불일치해도 전체 불일치로 올리지 않는다.
급여별 한도나 우선 선정 순위는 자격 필수 조건으로 승인된 근거가 없으면 탈락 조건이 아니다.

## 8. 미확인 원인과 담당 행동

`UNKNOWN`에는 복수 원인을 허용하며, 원인별 담당과 해결 방법을 함께 남긴다.

| 원인 | 예 | 다음 행동 |
| --- | --- | --- |
| 사용자 정보 부족 | 해당 자녀 입학 연도 미입력, 모름·건너뛰기 | 유효한 규칙에 필요한 최소 질문; 답하지 않아도 후보 유지 |
| 정책 근거 부족 | 기준일·거주 정의·예외 미제공 | 운영 검수자가 공식 자료 보완; 사용자 질문 반복 금지 |
| 정책 근거 충돌 | 같은 정책의 대상·금액 설명에서 학교급 불일치 | 충돌 범위 판정 보류, 우선 근거 결정 기록 |
| 정책 규칙 유효성 상실 | 적용 연도 변경, 규칙 의존 원문 변경 | 영향 규칙 재검수; 유효한 공개 범위만 미확인 안내 |
| 사용자 답변 충돌·시점 부적합 | 같은 자녀의 서로 모순되는 입학 답변 | 확인·정정 질문, 임의의 답변 선택 금지 |

값은 `KNOWN`, 명시적 제한 없음, 명시적 비해당, 누락, 미해결을 구분한다.
누락을 0·false·무제한으로 바꾸지 않는다. 선택하지 않은 가족 특성을 자동으로 ‘아니요’로 해석하지 않는다.
사용자 답변은 알려진 값·명시적 아니요/비해당·모름·건너뛰기·아직 묻지 않음을 구분한다.
질문 재사용 키는 **속성 + 대상 인물 + 산정 기준 + 기준 시점**이다. 주민등록지와 학교 소재지는 다른 질문이다.
필요한 정밀도까지만 묻고 진단명·상세 병력·상세 주소는 이 v1 질문 범위에 추가하지 않는다.
서버 재계산을 설계하되 답변의 장기 프로필 저장을 이 문서에서 결정하지 않는다.

## 9. Hard / Soft / Ranking의 의미

분야 탐색 관문과 다음 세 역할을 혼동하지 않는다. 같은 속성도 정책 근거에 따라 역할이 달라진다.

| 역할 | 의미 | 예 |
| --- | --- | --- |
| Hard | HUMAN 검수된 필수 자격 조건·제외·예외와 연결한 비교 | 특정 기준일 주민등록, 해당 자녀 입학 사건 |
| Soft | 사용자 필요·선호와 지원 방식의 관련성 | 교복 선호와 방문학습의 차이, 희망 이용 방식 |
| Ranking | 남은 후보의 설명 가능한 표시 순서에 쓰는 정보 | 명시한 우선 필요, 관련 시점, 제공 방식. 자격 UNKNOWN 자체에 감점하지 않음 |

Hard 미확인은 실패가 아니다. Hard 실패도 모든 대체 경로·수혜자와 예외를 해결해야 전체 제외가 된다.
생애 단계는 기본적으로 관련성·순위에 사용하고, 원문에서 필수 사건·대상 조건임이 확인된 범위만 Hard로 쓴다.
전국 정책과 지역 정책에는 기본 가산점을 주지 않는다. 지역은 실제 적용 범위를 비교하는 정보다.
사용자가 명시한 우선 필요를 추천의 중심으로 삼으며, 금액은 서로 다른 목적·지급 단위를 섞어 일반 순위를 만드는 기준으로 사용하지 않는다.
구체적 정렬 우선순위·질문 효용 계산·종료 기준은 적응형 추천 구현 설계에서 단일하게 정의한다.

## 10. 현재 자격·미래 가능성·접수 상태

현재 자격과 미래에 다시 확인할 가능성은 별도 결과다.
현재 `INELIGIBLE`인 정책을 미래 가능성이 있다는 이유로 현재 통과로 바꾸지 않는다.
사용자가 입력한 예정 사건과 검수된 미래 적용 근거가 있을 때만 미래 확인 대상으로 안내한다.
사용자의 진학·출산·이사·소득 변화를 자동 예측하여 미래 자격을 계산하지 않는다.

접수 상태는 `OPEN / CLOSED / UNKNOWN`이며 검증된 신청 일정과 판단 시각이 있어야 앞의 두 상태를 부여한다.
구현 설계의 `SCHEDULED`는 확인된 미래 신청 일정을 안내하기 위한 표시 구분이며, 접수 상태와 별도의 시점 정보에서 도출한다.
정책 적용 기간·급여 기간을 신청 기간으로 사용하지 않는다. ‘상시’·‘예산 소진 시’만으로 현재 OPEN을 확정하지 않는다.
접수 종료와 자격 불일치는 별도다. 종료된 회차를 지금 신청 가능한 후보처럼 표시하지 않으며, 향후 모집이 확정되지 않았으면 다시 열린다고 약속하지 않는다.

## 11. 교육 표본에 적용할 결정

아래는 보존 표본을 이용한 처리 계약이다. 실제 현재 판정은 최신 근거 확보와 HUMAN 결정을 거쳐야 한다.

| 표본 | 결정 | 공개·비교 전 남은 일 |
| --- | --- | --- |
| E03 기장군 교복비 | 입학 연도·기준일 거주지·학교 소재지·교복 착용·전학/재입학과 제외를 같은 자녀 경로에 연결 | 비어 있는 선정기준만 보지 말고 대상·지원내용 대조, 현재 공식 근거 확인 |
| E04 관악구 입학준비금 | 거주·해당 연도 입학·서울 밖 학교 등 원문의 AND를 보존하고 중복 지원 조건 연결 | 조건·예외·적용 시점 검수; E05와 별도 정책 유지 |
| E05 금천구 입학준비금 | 초등 경로의 대상·지원내용 충돌은 정책 원인 UNKNOWN; 질문 추가로 해결하지 않음 | 학교급 충돌 해결, 공개 표시와 다른 경로까지의 영향 검토, 현재 일정 확인 |
| E06 다문화 교육활동비 | 연령과 출생일 구간의 적용 연도 확인; 교육급여 미수급을 소득 50% 초과로 치환 금지 | 연도·연령 기준·소득 산정과 실제 수급 조건 각각 검수 |
| E12 다자녀 입학축하금 | 출생순위·입학·부모 한 명과 해당 자녀의 거주 기간을 같은 사건에 결합 | 주민등록·실거주와 기간 정의 검수; 첫째 입학과 셋째 순위 합산 방지 |
| E20 시설 운영자 융자 | 유아숲 목적 라벨과 가족의 실제 수혜 경로를 분리; 운영자 융자를 가족 교육 추천에 넣지 않음 | 가족 신청·이용 경로 근거가 없으면 범위 제외 유지, 원본·기존 AI 이력 보존 |

## 12. 갱신·철회·롤백

원본·정제·분류 사전·목적 사전·규칙 버전이 바뀌면 의존 범위의 유효성을 다시 평가한다.
기존 결정은 지우지 않고 새 버전과 연결하며, 변경 영향이 불명확한 관련 범위는 재검수로 둔다.

| 변경 | 즉시 행동 | 복구 조건 |
| --- | --- | --- |
| 분야 라벨의 근거·사전 유효성 상실 | 해당 분야 추천 적용 중단 | 현재 버전의 의미 검수와 공개 결정 확인 |
| 조건 규칙만 만료·변경 | 해당 규칙의 확정 비교 중단, 공개·라벨이 유효한 범위는 UNKNOWN | 현재 규칙 HUMAN 승인 |
| 공개 표시·목적·수혜 경로의 관련 근거 변경 | 해당 공개 결정 무효화, 추천 중단 | 새 근거의 HUMAN 공개 결정 |
| 출처 충돌 또는 정제 의미 손실 발견 | 영향 값·규칙·표시의 사용 중단 | 충돌 해결·정제 수정 및 영향 범위 재검수 |
| 배포된 변환·추천 코드 오류 | 운영 담당이 영향 경로를 중단하고 이전 검증 배포로 복구 | 현재 근거와 호환되는 공개·규칙 묶음 확인 |

규칙이 오래되었다는 이유만으로 유효한 공개 라벨까지 자동 폐기하지 않는다. 반대로 원문 변경이 공개 근거에도 영향을 주면 규칙만 UNKNOWN으로 낮춰 계속 노출하지 않는다.
이전 공개 묶음으로 돌아갈 때도 현재 근거와의 유효성이 필요하다. 오래된 승인이나 예전 신청 기간을 복원하여 공개를 재개하지 않는다.

## 13. 현재 구현 공백과 구현 전 인계

현재 `PublicPolicy`는 표시 텍스트·링크 중심이며 지원 경로·규칙·근거·검수 범위·접수 검증 상태를 제공하지 않는다.
`public-data.ts`는 활성 후보의 정제 표시값을 읽는다. 이것을 v1 HUMAN 공개 관문으로 간주할 수 없다.
현재 분야 매칭은 텍스트 정규식이며, 라벨·세부 목적·조건 규칙을 이용한 추천 엔진이 아니다.
현재 입력의 자녀 ID·출생 정밀도·목록 완전성은 활용하되, 학교급·입학 사건·출생순위·부모 거주 이력 등은 별도 의미 계약이 필요하다.
기존 AI 라벨 검수 저장 기능은 보존한다. 목적 사전, HUMAN 공개 결정, 조건 규칙 승인·의존성, 판정 이유·미확인 원인 계약은 후속 구현 대상이다.

| 책임 | 인계 산출물 | 완료 기준 |
| --- | --- | --- |
| 데이터·정제 담당 | 현재 공식 근거와 원본/정제 대조 묶음, 변경 영향 목록 | 출처·버전·필드 경로·누락·충돌 재현 가능 |
| 정책 인간 검수 담당 | 경로별 분야·목적·대상 결정, 공개 결정, 규칙 승인·보류 목록 | 승인 범위·근거·시각·버전·미해결 사유 명시 |
| 추천 구현 담당 | 서버 판정·질문·순위 계약, 설명 응답, 평가 사례 | 이 문서의 관문·삼상태·대상 결합을 구현 설계와 일치시킴 |
| 운영·릴리스 담당 | 공개 묶음 명세, 적용 기록, 중단·롤백 절차 | 영향 경로를 식별해 중단하고 유효한 묶음으로만 복구 가능 |

인간 검수 담당자 지정, 최신 공식 자료 확보, 최초 공개 경로의 HUMAN 결정과 규칙 승인은 아직 완료되지 않았다.
E03·E04는 첫 검토 후보이며 이 문서가 공개를 승인하지 않는다. 규칙이 부족하면 허용된 공개 범위에서 미확인 안내까지만 제공한다.
이 문서는 설계 산출물이며 제품 구현, 데이터 변경, 자동 테스트 실행 또는 추천 품질 검증 결과를 보고하지 않는다.
