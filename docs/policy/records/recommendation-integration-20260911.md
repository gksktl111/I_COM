# 추천 엔진 연결 구현 — 2026-09-11

사용자용 상태는 [핵심 안내](../README.md), 작업 순서는 [구현 계획](../work/recommendation-plan.md)을 따른다. 이 기록은 코드 연결 완료와 실제 정책 공개 대기를 구분한다.

## 구현 결과

- `recommendation/bank-facts.ts`: 질문 사전의 attribute/subject/basis/reference를 유지해 기존 답변을 조건 엔진에 전달한다. 학교 소재지의 시도·시군구를 별도 사실로 만들고, 현재 가구 거주를 자녀의 과거 거주로 바꾸지 않는다. 출생연도는 날짜 범위, 임신 주차·출산 경과는 구간으로 유지한다.
- CHILD/PERSON/EVENT/HOUSEHOLD를 구분한다. 건강 지원의 본인을 선택하면 저장된 자녀 프로필이 있어도 그 자녀에게 조건을 적용하지 않는다. 선택 대상 수를 실제 가구원·자녀 수로 쓰지 않는다.
- `server/guided-recommendation.ts`: 기존 CATEGORY_BANK_V1 요청을 확장한다. 기본 입력과 별도 `ruleAnswers`, `questionCount`, `catalogVersion`, `contextKey`를 받아 검수된 조건·추가 질문·결과를 연결한다. 추가 답변은 서버에 등록된 질문·버전·선택 대상·선택지만 허용한다. 기본 확정 답변의 변경은 기본 입력 수정으로 처리하고, 추가 질문으로는 기존 범위 안의 정밀화만 허용한다.
- `CategoryRecommendation.tsx`: 두 번째 입력 과정에 추가 조건 질문을 연결한다. 질문 중 카드 없음, 모름·건너뛰기, 5문항 뒤 계속/종료, 입력 수정 시 추가 답변 초기화, 취소·재시도·이전 응답 무시를 지원한다. 결과는 최대 20개·앞 최대 5개 강조이며 잠정 추천과 조건 비교 결과의 안내를 구분한다.
- `server/recommendation-sources.ts`: 동일 ACTIVE 행에서 공개 표시 데이터와 스냅샷·정제 버전·표시 해시·전체 정제 JSON의 SHA-256을 함께 읽는다. 서버 키·원문·내부 메타데이터를 결과 카드에 내보내지 않는다.
- `server/released-catalog.ts`: 실제 검수 결정과 초안 digest를 연결한다. 승인 뒤 초안·질문 변경은 재검수 대상이다. 원본 메타데이터 변경·검수 만료는 해당 정책을 제외한다. 이미 조건 비교로 전환한 분야는 이때 문구 점수로 자동 복귀하지 않는다. 조회 오류는 503으로 처리하며 부분 목록을 성공으로 내보내지 않는다.

응답 저장소·DB 스키마·수집 로직은 이번 추천 연결 때문에 변경하지 않았다. 기존 별도 수집 변경은 그대로 보존했다. 원문 태그를 자동 추출해 자격 규칙으로 승인하는 기능은 포함하지 않는다.

## 실제 교육 정책 자료와 공개 절차

[공식 확인 기록](../../fixtures/policy-recommendation/education-official-review-20260911.json)과 `server/catalogs/education-2026.ts`에 실제 교육 정책 두 건의 근거를 정리했다. 기장군 교복 지원과 관악구 입학준비금의 6개 지원 경로·19개 규칙·12개 질문 초안이다. 저장 원본 두 건의 현재 메타데이터를 읽어 연결했으며 DB 내용은 수정하지 않았다.

**현재 공개 결정은 0건이다.** 정책 `HIDDEN`, 규칙 `UNREVIEWED`, 불완전 경로와 접수 상태 `UNKNOWN`을 유지한다. 따라서 실제 공개 요청은 교육도 잠정 추천이다. 테스트에서 사용하는 승인 결정은 합성 검증용이며 실제 registry에는 등록하지 않는다.

다음 담당자는 아래 순서로 공개할 범위를 확정한다.

1. `educationOfficialSources`와 `educationReviewGaps`를 함께 읽는다. 기장의 대안기관·중복지원 범위, 관악의 전·재입학 예외와 신청 경로·서류 충돌을 확인한다. 저장 원문과 공식 공지가 다르면 현행 근거를 선택한 이유를 남긴다.
2. 확정할 경로만 보완한다. 미해결 내용을 임의로 complete=true로 바꾸지 않는다. 현재 초안은 불완전 경로라 사용자 질문을 늘려도 확정 자격으로 전환되지 않는다.
3. 공개·규칙·질문의 실제 검수자와 결정 근거를 기록한다. `recommendationDraftDigest(draft, policyId)`가 반환하는 digest, 검수 시각과 유효 종료 시각을 `educationReviewDecisions`에 등록한다. digest에는 정책·전체 질문·원본 메타데이터가 포함되므로 수정 후 다시 계산한다.
4. 같은 가족 입력으로 공개 전후 결과와 제외·미확인 이유를 비교한다. 두 사례가 준비된 뒤 교육 20건 표본과 다른 분야를 확장한다. 해당 분야의 전환 후 목록은 승인된 정책으로만 구성되어 초기 노출 수가 줄 수 있다.

AI 보조 라벨의 VERIFIED나 사용자의 일반적인 구현 요청을 실제 정책 내용의 인간 검수 증거로 쓰지 않는다. 정책 근거를 보완할 일과 사용자에게 물을 질문을 구분한다.

## 같은 날 후속 구현 — 검토 중 근거 변경과 재시작

공식 근거 추가 조사에서 관악 중복지원 확인 대상에 서울시교육청 지원이 포함됨을 확인하여 질문·규칙 초안에 반영했다. 기장 대안교육기관 질문은 법적 정의와 인가 여부를 명시했다. 기장의 다른 교복비 지원액 공제 규정과 2026 공고 환수 안내는 대조가 남아, 일괄 탈락이나 차액 자동 산정 규칙을 추가하지 않았다. 근거의 직접 열람/검색 색인 차이는 [추가 조사 기록](../../fixtures/policy-recommendation/education-review-followup-20260911.json)에 보존했다. 카탈로그·질문 버전은 `education-official-draft-20260911-r2`이며 공개 승인은 여전히 0건이다.

추가 질문에 답한 뒤 원본·검수 기간·기본 입력이 달라지면 예전에는 일반 오류 재시도로 동일한 잘못된 문맥을 반복 제출할 수 있었다. 서버는 이제 이 경우 409로 구분하고 화면은 **최신 조건으로 다시 확인**을 제공한다. 기본 질문 답변은 유지하고 추가 답변·질문 수·문맥만 초기화해 재요청한다. 원문 변경이나 검수 만료로 보류한 정책 수를 응답해, 자격 불충족과 구분하여 안내한다.

### 교육 20건 비교와 잠정 분류 교정

[전후 보고서](education-comparison-20260911.md)와 [재현 JSON](../../fixtures/policy-recommendation/education-comparison-20260911.json)에 보존 20건·30개 매핑 경로·9개 입력 시나리오를 기록했다. 기존 문구 필터는 E03 기장 교복 지원을 누락했고 E18 대청장학금(대학생 지원)을 후보에 넣어 5개 시나리오에서 상위 5개에 노출했다. E20 시설 운영자 융자는 기존 후보에도 없었다.

`server/provisional-classification.ts`로 확인된 두 분류만 보정했다. ID와 이름·요약·기관·목적·대상·조건·급여·출처 URL의 지문이 맞을 때 E03을 교육 후보에 넣고 E18을 제외한다. 분류 근거 내용이 바뀌면 이 보정을 재사용하지 않는다. 다른 정책·분야는 기존 탐색을 유지하며, 이 보정은 자격 비교·HUMAN 공개 결정이 아니다. 2026-09-11 현재 ACTIVE 원본을 별도 읽어 두 지문과 보정 결과가 실제 저장 내용에도 일치함을 확인했다. DB 변경은 없다.

비교 도구는 수정 전 필터를 고정한 baseline과 수정 후 실제 guided 분기를 각각 실행한다. 9개 시나리오 모두 E03 추가·E18 제외를 확인했다. 실제 흐름은 계속 PROVISIONAL이다. 내부 초안 두 건은 모두 UNKNOWN이고 나머지 18건의 실행 규칙 미구현을 자격 탈락과 구분했다. 즉 분야 발견 결함은 수정했으나 개인별 자격 정확도·전체 카탈로그의 최신 순위·교육 20건 전체 규칙 적용을 검증한 것은 아니다.

관악 현행 제1835호 조례 전문도 추가 확보했다. 제3조는 구청장이 정한 기준일, 외국인 등록지 포함, 1학년 입학생 및 타 시·도·국외 전입 1학년 학생을 규정한다. 조례의 이 범위를 2026 개별사업의 확정 조건으로 즉시 대체하지 않고, 공고와의 적용 관계를 검수 항목으로 남겼다.

최종 검증은 관련 자동 테스트 **96개 통과**, 변경 파일 lint 통과, webpack 프로덕션 빌드·TypeScript·18개 정적 페이지 생성 통과다. 브라우저는 19회 모의 요청으로 409 복구와 기존 질문·수정·취소 흐름을 확인했고 테스트 브라우저·서버를 정리했다. 이후 서버 분류 변경에는 해당 회귀 테스트와 최종 빌드를 적용했으며 UI가 같아 브라우저 검증은 재사용했다.
